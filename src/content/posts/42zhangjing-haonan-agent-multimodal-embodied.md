## 一、核心观点

### 1. 从 Agent 转向多模态，不是因为 Agent 不行，而是「这一年会被消耗在造数据上」

淏楠在 MiroMind 做的是纯语言 Agent——搜网页、读新闻、写报告那一类，参与 Mid-Training 与 SFT，主攻 Web Search 数据的构造。他复盘自己 2025 年底的判断：「如果我作为 Agent，大概率是以造数据为主干一整年，我会觉得这个东西对个人的积累、或者成长，可能不是特别有利，对我来说不够有趣。」这句话点出了当时 Agent 团队的真实分工结构：模型能力的天花板在基座，一线工程师的手感全在数据上，而「Agent 数据长什么样、应该怎么造、MCP 应该是啥，当时都没有特别特别清晰」。他并不否认 Agent 是主线——恰恰相反，他认为 Agent 是「人机交互非常合理的方案」，也是交互的主线；他只是判断在这条主线上，自己那一年能获得的东西不如换一条路。这个取舍的参照系不是「哪条路更有前途」，而是「哪条路能让我长本事」。

### 2. 国内外 RL 的真实差距不在 infra，而在卡——卡少则实验少，实验少则积累慢

这是本期最反直觉的一段。外界普遍认为国内 RL 与海外有明显代差，淏楠把差距拆成三层：工程实践与 infra 层面「代差其实没有那么大」，代码这套东西并不是写不出来；真正的短板是算力——「最大的 gap 我觉得可能还是卡，就是 RL 还是费卡」。因为卡少，能跑的实验就少，能并行验证的想法就少，能坚持训练多久也受限，于是「你的积累和经验，整体就跑得慢了」。他甚至给了一个非常具体的比较口径：假设同样租某家云一个月，在一个月内要把分数往上推，「那确实就是暴力往上刷的能力最强的那家效果最好」。这解释了为什么国内 RL 论文不少但产品体感落后：不是不知道怎么做，而是试错次数被预算卡住了。

### 3. Agent 与多模态不是两条平行线，而是「以 Agent 为主线做多模态」

外界习惯把 Agent 和多模态当成两个赛道，淏楠在混元的实际做法是把它们焊在一起。他们想做的是「多模态里的 Cursor」——内部代号 Hunyuan Creator：模型生成三段视频，你用 1/2/3 选一段，第 4 个选项是「都不满意」，然后你写「我希望在第 1 个方案上再怎么样」，它继续改。这个交互设计的本质是把代码补全里「Yes / No / Reject / 追加指令」那一套搬到视频上。他的理由是：Agent 的能力主要来自后训练，而多模态的后训练恰好是跟 Agent 结合最紧的地方，所以「围绕着 Agent 这整套的使用方法去搭建多模态」，比单纯做一个生成模型更 make sense。这也解释了 UniRL 的命名——「Uni」指的是理解与生成的统一，「理解能帮助生成，生成不一定能帮助理解，但理解一定能帮助生成」。

### 4. 视频生成没有 R1 时刻，这是他们做了半年后最痛的结论

2025 年底到 2026 年初，团队一度相信视频生成里会跑出 R1 那样的时刻——「当时我们年初认为是有的，然后后来做了半年发现，不行，就是它并不存在比较 efficient 的 scaling law」。他们试过加 caption 改写，也不行，模型的提升仍然集中在「运镜、连贯性」这类偏感知的维度上，而不是推理。对比语言模型，他认为语言之所以能靠后训练起飞，是因为 pretraining 的 scaling law 之外还有一层 test-time / 后训练的 scaling law 可以吃；而视频生成当下的进步「更偏 pretraining」。他甚至直言多模态的 R2 现在「好多家都还没 work」——即便有团队 work 了，能力提升的来源仍然是前置的大规模预训练，而不是后训练撬动的推理。

### 5. 视频生成的竞争没有想象中激烈，因为 infra 便宜、数据没法抄

这条判断对创业者极不友好，但对理解格局很关键。淏楠说 infra 是「便宜的」：「弄了十来个比较有经验的同学，两个月的时间都能推到一个相对 reasonable 的水平，而且 infra 全部开源自研做得比较好。」真正的壁垒是数据，而「data 就是纯是看你自己的积累，走不了捷径——你要不就花钱，你要不就有产品，帮你做数据的回流或者数据的积累」。他因此下了结论：「最后我看下来，确实是得在那种有产品的地儿做这东西，才能做得撑。」这也解释了为什么视频模型最后收敛到少数几家有流量入口的公司手里：不是模型难，是数据管道贵且不可复制。他自己也承认，当年「完全没经验」地尝试过一波，没成。

### 6. Seedance 2.5 是当下的天花板，但只到 60 分；抽卡会长期存在，只是意义变了

被问现在最好的视频模型处在什么位置，淏楠给的是 Seedance 2.5，并给了一个少见的量化判断：「我觉得还在半山腰，就是他们能做到 100 分的话，那他们现在应该做到了 60 分。」他判断 AI 短剧的能力「没有到头」，做到接近电影质感没问题——他提到从《被裁掉的女孩》到后来刷到的《无敌超人》，已经「几乎达到了 Netflix 的水平」，但也提醒那里面有大量专业人力的介入。至于抽卡，他认为不会消失但会变质：现在是「质量崩坏」导致的抽卡，未来是「taste 分歧」导致的抽卡——「它都很好，只是你和我的偏好不一样」，你选的是刘德华还是陈道明、用哪种镜头语言。所以真正的产品机会不在模型，而在「harness」：一个让普通人能用上电影级质感的交互中间层。

### 7. 视频领域的 harness 比 code 更重要，因为 code 有最优解、影片只有 taste

这是他反复强调的一个产品洞察。代码的评判标准是收敛的：「我们都希望 code 能达到又快又好、又整洁又好读，这都是大家公认的标准。」但影片不是——「它很多时候希望自己去施加一些影响」，用户要的是把自己的审美压进去。所以多模态生成里的 Agent harness 不是在提效，而是在表达。他拿小红书举例：小红书的编辑页面「就好很多」，是一种可用的中间层雏形；但行业里还没有一款真正成熟的 harness，能套在「有电影质感的模型」上，把能力最大化。他预言未来半年到一年，门槛会被拉下来，「形成一个既是生成者、又是消费者的平台」。这句话是本期对视频赛道最明确的一个时间点下注。

### 8. 实时互动分两种，大家其实都还在第一种，而且第一种也不成熟

淏楠把实时互动拆成两类：**伪实时**——生成速度快于消费速度，「其实还是在你说完它生成，只是生成速度足够快，让人觉得有点像实时互动」；**真实时**——模型真的能跟你的对话做反应。他认为「大家应该都在第一条路线」，而第一条现在也没成熟，因为加速必然牺牲一致性：scheduler 的降噪步数、tcache 跳层、蒸馏、宋扬那套 consistency 一步生成，全都会让画面「更容易崩」——镜头转回来，「后边的东西就变了，或者人脸就变了」，看起来「有点像盗梦空间的那种感觉」。他举 MiniMax H3 为例：外网很火、有人接进直播间，但他自己用过也训过它的后训练，「体感上面没有那么容易，还是很慢的」。结论很务实：「保质量比保住 realtime 更好」；对真实时他「有一点点悲观」，因为模型为了更好的连贯性只会越做越大，「天然就更慢」。

### 9. 世界模型的迷茫，来自把手段当成了目的

这一段是全场最锋利的地方。曲凯提到很多人做世界模型「做迷茫了，不知道东西做了 for what」，淏楠的回应是：这个事从研究角度大家一直都知道非常难、短期做不出来，「不可能说大家以为能做，然后做了一下发现做不出来」——是市场情绪把它架在了那个位置。他更狠的一问是：「首先你不一定能做出来，其次做出来你能干啥呢？」很多小厂做 video world model，「大家讲的做出来就是为了具身」，但「你要做具身，为啥不就做具身呢？」他拿李飞飞的 World Labs 和 LeCun 的 AMI 对比：两家都叫世界模型，做的东西完全不一样；李飞飞一路在写「什么是世界模型」的定义、走 3D 建模路线，LeCun 那条根本不需要你把草、叶子、光线都建模好——「你可能就是理解加做 Action，这个就做具身就足够了」。他描述的实际演化是：先理解当前状态、Action 一步、再理解下一步，那条「先建模整个世界再行动」的路慢慢「变味了」。

### 10. 具身的两条正确路线：Astra 之前是「一个巨大模型」，之后是「上下两套系统」

他给具身的技术路线分了两拨人。第一拨想做巨大的模型——「在 Astra 就是 GPT-6 出来之前，很多人在做这个，希望出现一个非常大的模型」，逻辑是拿大厂现成的视频生成/大模型调一下做具身，这「很像 Astra 他们的逻辑」。但 Astra 之后，这条路对初创基本关闭：「并没有这个技术积累，也没有这个金，也没有这个卡，也没有这个钱」——具身公司现在最高估值约 200 亿人民币，账上五六十亿，「都不到十亿美金」，跟真搞模型的没法比。于是第二拨、也是他认为具身公司应该做的，是「两个系统」：「上面套一个，底下再套一个」——底下是自己本体上训的 7B–16B 小模型，负责真实的操控与数据闭环；上面接一个通用大模型，负责常识、理解与兜底。这也顺带回答了大厂能不能做具身：不能，"具身不太够赚钱"，它是"更像车或者手机行业"的长产业链生意，大厂对产业链的控制力天然弱。

## 二、关键问答

**Q：你在 MiroMind 做 Agent，为什么会在 Agent 最热的时候转去混元做多模态 RL infra？**
A：他自己给的因果很朴素：2025 年底意识到，作为一线 Agent 工程师，接下来一年大概率「以造数据为主」——做 Web Search 数据、摸索 Agent 数据长什么样、MCP 该怎么定义。这些事对公司有价值，但对他个人的积累「不够有趣」。刚好庞天宇拉他去腾讯做图片视频生成，问他要不要做 RL infra，他就去了。他自嘲这是「反而选了一个可能对自己成长没有帮助的事」，但补了一句关键：RL infra 是他当时判断「很重要且我很感兴趣」的方向。

**Q：Agent 和多模态，从个人职业发展看怎么选？**
A：他把这层看得很透，用「围城」形容：做 Agent 的「天天洗数据，没劲」，做 video 的「觉得 video 不体现智力」，2026 年初做 GUI 的甚至觉得这一波「快黄了」。但他认为 Agent 有一个天然好处——「你在大主线上，比如你公司做得不好，你可以换下一家公司，但你还在主线上」。多模态的优点是工作体验更有意思：审数据时「看视频比看他给我爬出来的 trace，一条条读，或者写规则去筛，过程上更有意思」；缺点是如果这家公司不做这个方向，你「没有什么很好的翻转方向」。

**Q：国内外 RL 的差距，到底差在哪一层？**
A：不在 infra。他说工程实践层面的代差「其实没有那么大了」，这套东西不是写不出来。差在卡：RL 特别费卡，卡少则实验少，实验少则经验积累慢。他给了一个务实的比较口径——同样租一个月云，谁能在一个月内把分数推得最高，谁就赢，而这本质上是「暴力往上刷的能力」的比拼，也就是算力预算的比拼。

**Q：Agent 和多模态这两条线，最后是怎么合到一起的？**
A：他的判断是「以 Agent 为主线做多模态」。理由是 Agent 的能力主要在后训练，而多模态最需要被解决的就是后训练与交互；所以他们做 Hunyuan Creator，定位是「多模态里的 Cursor」——生成三段视频让你选，第四项是「都不满意 + 追加修改要求」。他认为完全不做 Agent 的多模态方案「也不太 make sense」。

**Q：多模态最后能怎么变现？转具身是硬跳还是顺滑过渡？**
A：他明确说多模态只有两条变现途径：「一方面是以 Diffusion 这条路接着做视频生成，另外一条路就是做生成 Action。」第二条就是具身——「Action 也是一种模态」，跟生成视频、生成音频是同一件事，只是把输出从像素换成动作。所以转过去很顺滑：具身的 Action 生成同样用 Diffusion 模型，逻辑与视频生成高度相近，「你也非常方便用原来自己的 codebase 试一把」，这批人后来被叫 World Action Model（转录作 WSD），早期转过来的人大多有 Diffusion 经验，「技术门槛没那么高」。

**Q：视频生成里会不会出现 R1 那样的时刻？**
A：他们赌过，输了。「当时我们年初认为是有的，后来做了半年发现，不行，就是它并不存在比较 efficient 的 scaling law。」加 caption 改写也没救回来，能力提升还是集中在运镜、连贯这些偏感知的维度。他的结论是：视频生成当下更吃 pretraining，后训练撬不动推理；多模态的 R2 现在好多家都还没 work。

**Q：既然视频模型这么强，为什么竞争反而没那么激烈？**
A：因为壁垒不在模型而在数据。infra 便宜——「十来个比较有经验的同学，两个月能推到 reasonable 的水平」，开源方案也成熟。数据没法抄：「data 就是纯看你自己的积累，走不了捷径，你要不就花钱，你要不就有产品帮你做数据回流。」所以「最后确实是得在那种有产品的地儿做这东西，才能做得撑」。他补了一句：这个方向「更吃资本，更吃大团堆」，不是一波厉害的人就能干起来的。

**Q：Seedance 2.5 现在大概是什么水平？**
A：他给的刻度是 60 分（满分 100）——「还在半山腰」。能力没到头，做到接近电影质感「没什么问题」，但他提醒现在那些惊艳的 AI 短剧里有大量专业人力介入。真正的短板是可控性与 harness：他自己试过「做一条短剧」，操作起来「还非常痛苦，context 管理也不好，各种都做得不到位」。

**Q：抽卡这件事会长期存在吗？**
A：会，但意义会变。现在是「质量崩坏」型抽卡——形变、关系不对、混进莫名其妙的东西；未来是「taste 分歧」型抽卡——每一条都很好，只是你和我的偏好不同，你选刘德华还是陈道明、用哪种镜头语言。他类比线下拍片：「某一段咔掉了，或者你好几段最后给导演来选一段」，导演的工作从「修 bug」变成「选表达」。

**Q：MiniMax H3 的实时互动，到底是什么水平？**
A：他的评价很直接：模型能力大概相当于 2.0 的水平（相对当前最强的 2.5/3.0 一档），「还是会生成不少废的 clip」，精细控制也弱。对比之下 Seedance 2.5 的强项是能插大量 reference image / reference video / storyboard，「一张图里包含好多张小图」，控制力强得多，H3 不具备。他补了一句公允的话：H3 在外网的传播确实有效，但「我是用过的，而且我还训过这玩意」，体感「没有那么容易，还是很慢的」。

**Q：实时互动的技术真的成熟了吗？**
A：没有。他把实时互动分真假两类，认为大家基本都在「伪实时」——生成速度快于消费速度而已；而「真实时」更像世界模型那条路，还很远。加速的技术手段（跳层、蒸馏、一步生成）都会牺牲一致性，典型症状是镜头转回来人脸就变了。所以他判断行业当前的取舍是「保质量比保 realtime 更好」，并对真实时「有一点点悲观」——模型为了连贯性只会越来越大，天然更慢。

**Q：为什么现在这么多人做世界模型做得迷茫？**
A：因为目的丢了。他的两连问是：「首先你不一定能做出来，其次做出来你能干啥呢？」很多小厂做 video world model 说是为了具身，但「你要做具身，为啥不就做具身呢？具身没有必要一定要走这条路」。他判断这轮情绪是市场架起来的，研究圈一直知道短期做不出来；而「先建模整个世界再行动」这条路正在变味——实际演化成了「理解当前、Action 一步、再理解下一步」。

**Q：李飞飞和 LeCun 都在讲世界模型，是一回事吗？**
A：不是。他拿 World Labs 和 LeCun 的 AMI 对比：李飞飞走 3D 建模路线，还隔一段时间就写一篇「什么是世界模型」的定义；LeCun 那条「不是说 OK 我建模整个世界」，不需要把草、叶子、光线都建模好，「你可能就是理解加做 Action，这个做具身就足够了」。他自己的立场偏后者，也因此在节目里说「身边的人都不 buy 他那个 3D 的路线」。

**Q：具身模型本质上要做什么？Astra 又为什么会让具身圈震动？**
A：他先说清具身模型的输入输出结构：输入视频、输出一个低维向量——「可能 20 多维」，每一维都有明确的物理意义，比如某个关节的角度。这和 VLM 输出一个 768 维的 latent 完全不同；让自回归模型输出「左边方括号，第一个数，逗号，第二个数……」这种数字串再解析成电机转角，「你怎么想怎么怪」，实际也不 work——这也是为什么之前没人相信大模型能直接替换中间那个模型。Astra 之所以震动，就是因为它真的按指令输出了一段有意义的动作序列，而且这段序列真能操控硬件，并且「是特意基于具身去训的」。他补了一个很硬的观察：Astra 能通过「动一下夹爪、看视觉怎么变」在多轮交互里建立视觉与动作的对应关系，「这个不就 RSI 了吗，这真挺强的」；对应的 reward 也很朴素——「我今天就是要拿到那个苹果，你视觉判断这段画面拿到苹果，就是一个 reward」。

**Q：OpenAI 内部是怎么做具身的？**
A：他听到的是两条线：一条是把具身当作大模型泛化能力的一部分，「就专门做 LM，只不过把具身当作其中一部分来泛化」；另一条是专门做具身的团队。而结果是——「最后发现堆到主线里反正是最 work 的」，专门做具身的那条线「有点不知道怎么做」，他们做的数据和能力提升最后都反哺给了 VLM，而 VLM 的提升又主要来自 LM。所以他的判断是：Astra 的具身能力本质上是大模型泛化的一次外溢，跟它搞定 Blender 是同一套逻辑。

**Q：具身的数据，真机遥操和虚拟仿真哪个更重要？**
A：看对谁。对大模型厂商，仿真数据很有价值——「它是一个很好的 environment，像个 game 一样」；对具身厂商不是，因为「具身厂商最后 care 的是你东西能不能落地，能不能操控它那台机器」，所以必须用 exactly 那个机型去踩 trace，失败的加 DAgger 让人接管继续跑成功。他给了一个很生动的仿真 gap 例子：抓瓶子，「你拿两个手指就能捏起来」，但真正想要的是五指贴合瓶身；如果全在仿真里学，「可能最后拿中指和食指给你捏起来了」，不符合你要的效果。除非仿真做得极好，否则 ROS→Sim→Real 那条路还走不通。

**Q：具身的「大脑」最后会不会变成大模型厂商的竞争？**
A：他的回答分三层。第一，「很多公司讲大脑是为了估值」，对估值确实有益。第二，从技术趋势看，Astra 之后行业确实在往「1 + 2」收敛——原本 System 0/1/2 的三段式，现在 0 和 1 合成一段，2 是那个最大的模型，「直接从本体的那个，和一个贼大的、Language Thinking 能力都非常强的上面的大脑，两个组合去推进」。第三，也是最现实的：具身厂商的卡「远远不够」，「可能你后边加俩零」都赶不上——大模型是五六家在分卡，具身是上百家在分剩下的卡。所以初创不必也不该去拼大脑，把本体、小脑、落地场景做好更实际。

**Q：那大厂为什么不太能做具身？**
A：两个原因。一是商业上不划算——「具身它不太够赚钱，相对于大厂的主线业务来说」，它是「更像车或者手机行业，产业链非常长」，大厂对这么长产业链的控制力天然弱，不像软件那样暴力。二是组织上做不了——「真要去做具身了，那你就扎根基层，看看这些素材怎么弄的，你就真是上手去摇操摇两条，在大厂是天然做不成」。大厂分工太细，「你干了别人觉得你 overreach 了」，这是「大厂固有的问题」，在所有领域都一样。

**Q：现在这个时间点去做具身，是不是「49 年加入国军」？**
A：他的回答是「不是」，但理由不是理性计算，而是志趣：「视频那块做那个不好吗？不是没机会，确实可以去大厂做这个，但这东西不是硬核生产力，它是给我精神享受的。」他说自己想做的是 physical AI——「把 AI 带到物理世界当中，以各种形式，只有到生活当中，你到 physical 领域，你才能改变大家的生活」。至于短期利益最大化，他答得更干脆：「当年就做 Agent 了」，MiroMind 那条线给过相当可观的 package，甚至有机会在北美 TikTok 做套在短视频上的 agent——「应该就在美国了」。

**Q：Agent 现在最缺的是什么？**
A：不缺智力，缺场景。「它的智力水平我觉得是完全 OK 的」，主线是让大家更好用，也就是 GUI / computer use 这一块，「核心还是一点，你怎么让大家用得上」。他认为 personal AI 是 Agent 这条线的终点，但当下「开发的场景还是不够多」，比如 game agent 就很少有人做。至于下一个爆点是什么，他坦率承认想不到，「这可能还是得看 Astra 下一波爆点是什么」。

**Q：多模态还有创业公司的机会吗？**
A：很难。他自己给的多模态判断偏悲观：「图片是没什么做的了，主要就是做视频」，而视频的门槛在数据与算力——「除创再重头 pretrain 自己的 video model，这个东西说实在不现实」，因为视频很贵，早年还能爬 YouTube，现在「一爬就封号」，各平台反爬都很成熟了。他认为小厂唯一的机会在那些「已经有很多视频、但还没做出来」的团队，以及 harness / 交互这一层。

**Q：具身创业公司真正的壁垒应该建在哪？**
A：他的答案是「硬件 + code design + 自己的小模型」三位一体。小厂不能去拼通用大模型，要「有自己的硬件，要不然怎么跟大厂做差异化」，然后「把自己的硬件和那个 System 绑定着做得更好，就是 co-design 的逻辑」，在上面套一个 Astra 之类的大模型，中间是自己调的 7B–16B 模型，最后「尽快地做落地」。他举了一个非常具体的场景：酒店叠被子——「酒店的地势平衡，你可以用轮式，而非双足机器人」，这个场景「既不是纯标准化，也不是非标化」，乱的程度不一样但边界清楚，是能做的。他还补了一句判断标准：「估值这么高，你想让它更高，你只能是真的落地。」

**Q：Astra 算不算具身的「GPT-3 时刻」？**
A：他觉得「确实有点算」，而且他的论证不是能力分数，而是数据闭环。假设你的模型成功率只有 50%–60%，在没训过的场景里泛化到 50% 已经很不错；失败了就「及时让 GPT 接管」，而这段接管数据「非常有价值，就被留存下来了」，回流后再训自己家的 7B/8B 模型，把成功率从 60% 推到 80%。随着成功率上升，GPT 调用量下降、人的负担下降，「这样你 scaling up 的逻辑可能才真的成型」。他类比 speculative decoding：「小模型先给你 draft 一遍，然后大模型无非就是 accept 或者 reject」——但反过来，「GPT 直接操作机械臂是不划算的，太慢了，太费了」。这套接管数据在行业里叫 error recovery，是数据里最有价值的部分之一。

**Q：Astra 的具身能力会被蒸馏出来、变成开源模型吗？**
A：他把蒸馏分两种。硬蒸馏——「真的让它揉出来 trace」，像语言模型那样，他认为具身里「蒸不了，成本过高，没必要」。软蒸馏——就是前面说的接管那两步，「你只蒸了这一两步」，量小很多，但「花的钱和大家的收益是 OK 的」，而且能把轨迹带回正常行为模式。他判断这种软蒸馏「大概率不是大厂在做，是具身厂在做」，因为「具身厂好布设备，好在素材里布这个东西」。

**Q：为什么没考虑 AI for Science？**
A：他其实想过，只是觉得时机不对。他把 AI for Science 分两拨：一拨是搞 science 的人用 AI 解 PDE/ODE——他举的例子是 WiFi 信号覆盖布点优化（大场景里有遮挡，怎么布最好）和流体力学；另一拨是「拿 AI 去帮化学做实验」，但这需要实验工厂，「你还是需要有一个……而非纯干实验的方式」。而「它不就跟具身线下的那些素材有点像？那素材也是工厂」。所以他的结论是：具身做好了也能帮到 AI for Science，但那条路现在做还偏早。

- UniRL：淏楠在腾讯混元主导的开源多模态强化学习框架；「Uni」指理解与生成的统一，核心理念是「理解能帮助生成」。
