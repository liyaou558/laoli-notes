## 一、核心观点

### 个人 Agent 的兴起，本质是「主动智能」这一新阶段

Alexander 把大模型产品的演进分成三波：第一波是聊天，第二波是编程 Agent，第三波则是本期主角「主动智能」。他打了一个很形象的比方：即使你拥有一个极其强大的编程 Agent，效果也像请了一位特别厉害的首席工程师，但这人却不肯看 Slack、不肯看 Linear，只有你亲自派活才会动手。资深用户能自己搭自动化让 Agent 更独立运转，可普通用户一般不会这么做。所以 Dots 要解决的核心问题就是：不用再全靠你自己费心，让产品主动提议、告诉你它打算做什么、怎么帮你。他认为这一时刻现在到来，是因为模型能力终于到位，能以更符合人们直觉的方式提供智能。

### 三个理念：持续做事、随处可得、它有自己的电脑

Dots 的产品设计可以抽象成几个关键理念，其中最重要的一个是「持续做事」。模型经过专门训练，能持续做事并主动推进任务——你可以让它长时间盯着一件事，比如「帮我盯着这个 PR」，甚至不必告诉它具体怎么解决，它会自己摸索；再往后还能交给它更开放的任务，比如「持续关注这个反馈频道」。另外两个理念是「你在哪都能找到它」——在任何工具里都能跟它说话；以及「你能做的它也能做」——因为它拥有自己的云端电脑，用的是它自己的电脑，而不是占用你的电脑。

### 人的使用习惯改变，是 Agent 落地不可或缺的条件

Alexander 特别强调了一点常被低估的因素：要让这些产品真正用起来，人也得做出很多改变。他举了「第零天」和「第四百天」的对比——一家团队刚用编程 Agent 时，大家都不知道该怎么用，Agent 也没接入任何工具；到了第四百天，Agent 已经接入了一堆工具、能获取上下文信息，大家也摸索出了成熟的使用方法。这个条件必不可少，因为一个想主动工作的 Agent，如果获取不到上下文信息，就没法真正主动帮忙。连接器（connectors）正是让大家能把自有数据接进产品、支撑主动性的基础设施。

### 独立身份是为了让普通用户「想通」能交给它什么

当被问到为什么给 Agent 独立身份、还让用户自定义，Alexander 给出两点理由。第一，特别聪明的深度用户能自己发现工具的高级用法，但普通用户面对一个没有独立身份的工具，往往只会让它「现在帮忙做一件事，做完就结束了」；可一旦一个有独立身份的对象出现在 Slack 里，大家一下子就想通了：原来可以让它做那些要花好几天、或不用连续盯着的事，比如持续跟进项目、汇报进展。第二，独立身份能让人明白「不管在哪里跟它说话，用的都是同一份上下文」。他自己的用法就是通勤时跟 Dot 语音通话，工作时在 Slack 各个讨论串里给它发消息、转发私信，还能在应用里直接说话——但无论在哪儿聊，Dots 都记得之前聊过的所有内容。

### 从「记住一堆 Agent 名字」的负担，反推出命名与界面设计

Alexander 直言大多数人记不住太多人名，更别提每个人若有八个名字稀奇古怪的 Agent——他拿极限飞盘品牌打比方，一想到五个 Agent 都叫不同飞盘牌子的名字，还要记住哪个是拓客、哪个是约饭用的，就觉得受不了。因此目前的判断是：支持一个人拥有多个 Agent，但普通消费者大概率只要一个，且这个 Agent 应像本人的延伸。产品上一个具体决定是：把你的 Agent 接入 Slack 或 Teams 时，名字前会加你的名字作前缀——他自己在 Slack 上叫 ae，于是 Agent 叫 ae.dot；你若起名 alice，就叫 x.alice。这个做法并非一开始就想对，而是开发中一不小心让大家创建了太多乱起名的 Agent，结果谁都搞不清 Slack 里到底怎么回事，才反推出来的。

### Space 是人与 Agent「同等地位」协作的工作区

Alexander 用很长的篇幅解释 Space 的定位：它不能说以 Agent 为先，而是让 Agent 和人以同等地位来协作。他从人协作的媒介切入——实时交流、发消息、文档（幻灯片也算文档），以及第四类专门做某件事的工具（如 Salesforce、Figma）。关键洞察是：一旦把界面做成一个个消息气泡的聊天形式，超长内容体验就不好；如果 Dot 想出 12 种帮你办法并发来 12 条消息，你反而未必高兴，但若它生成一个空间、在里面建个页面放一张待办清单，你会挺开心。Space 里还能给 Agent 设定指令（类似代码仓库里的 agents.md），并天然融入 HTML/CSS 生成的可视化图表、可点击交互原型——因为人本来就难手写 HTML，而 Agent 恰好擅长。

### 安全与信任：最强、最值得信赖，起步刻意保守

Dots 与 Muse、GrokBot、Instinct 等相比，Alexander 只归纳两点差异：能力最强的 Agent，以及最安全、最值得信赖的 Agent。围绕「值得信赖」，他们在能力、产品功能和推出方式上都做了取舍。模型层面选了对齐做得最好的 GPT-6 Astra；跑在 Codex Harness 里并针对安全重做评估，其中给 Agent 发邮件、尝试提示词注入数据窃取的测试「没有一次成功」。产品默认行为很保守：主动用你接入的工具做研究、琢磨怎么帮你，但在你确认前不采取实际行动——发现日程冲突不会直接改会议，而是问「要我帮你改吗」；知道同事问题的答案也不会直接发出去，而是先问你要不要发。他还特别澄清：媒体报道的 Agent 失控事件用的是原本不打算发布的内测模型，沙箱隔离也未达到产品级水平。

### 全天候定价：想要一笔固定月费，避免任务因额度耗尽而落空

Dots 的用量不计入套餐限额，且 Alexander 明确说这是永久的设计，不是短期促销。他为 A2A 听众展开解释了原因：如果用 Codex 把额度用完了，再让它做事它就会停下来，体验很糟；若这是个持续运行、你指望它照应的 Agent——比如「帮我盯航班和路况，该出发时帮我叫 Uber 去机场」——结果你前一晚写代码用太多，它就不干活了，这绝不可接受。他们定下的原则是：Dot 应该全天候随时可用（滥用除外），且随时都能很快回复。定价更像「请人接活」——你付固定月费就能联系上它，干多少活取决于付多少；想要更强（更强电脑、更强模型、跑得更快、并行更多）可选更高一档固定月费。额度与主 Codex 额度分开，模型还会主动提醒「我接下来要用更省钱的模型了」「这事急吗，不急就放到夜里做更省」。

## 二、关键问答

Q: 为什么个人 Agent 的时刻会在现在到来？
A: Alexander 认为核心是模型能力终于足以支撑这样的体验——操作浏览器、操作电脑这些能力真正发展起来了，大家也逐渐摸清了 Harness 该怎么做。他把这归为「主动智能」阶段：此前即使有强大的编程 Agent，也像一位不肯看 Slack、不肯看 Linear 的首席工程师，只有你派活才动手，普通用户不会自己搭自动化。现在终于能以符合直觉的方式提供智能，让产品主动提议、不用全靠用户费心。

Q: 加入 OpenAI 两年多来，你一直想做的产品形态是什么？
A: 他坦言自己有个大致想法：聊天已经很强大，AI 会改变世界，但要让模型更有用还有很多容易做的改进——一是让它能做事，二是不用让用户自己琢磨该让它做什么。他至今上推特看到别人跑各种循环任务，心里都会有点觉得自己不行。他甚至直言这是「你越熟练就越觉得自己不足」的一类产品，挺难受的，所以想把这些问题弄清楚。

Q: 为什么决定给 Dot 独立身份，还让用户自定义？
A: 两点理由。一是普通用户面对没有独立身份的工具，往往只用它做「一件事、做完就结束」，而有独立身份的对象出现在 Slack 里，大家一下就明白可以让它做要花好几天或不连续盯着的事。二是独立身份能帮人理解「无论在哪儿跟它说话，都是同一份上下文」。他也承认 Agent 该不该有独立身份、每人几个 Agent，这些还得整个行业一起摸索，个人与企业用户可能答案不同。

Q: 为什么把与 Dot 交流的界面做得很简单，像在跟人发消息？
A: 他引用 Sam 的观点：人类世界围绕人塑造，工具也围绕人设计。个人生活用 iMessage，每个人只对应一个对话；工作用 Slack 或 Teams，有频道和分支讨论、更高级的控制。这些产品各自发展却变得相似，背后有原因可以借鉴。所以决定把它做得像跟另一个人发消息，以后再提供更多方式把工作中不同上下文分开——这就是 Space 与 Dots 配合的由来。

Q: Space 是什么，在产品规划里什么位置？
A: Space 是一个协作工作区，让 Agent 和人以同等地位协作。他举例：过去写文档要先搭框架，再切到 Slack 找同事补内容；现在可直接在文档里 @ 自己的 Dot，让它展开、调数据、问人某件事做完没有、做完就把框勾上，从而进入很深的心流。页面还能设定指令（类似 agents.md），并天然融入 HTML 生成的动态图表和可点击原型，因为它比普通文档格式丰富得多，而 Agent 恰好擅长 HTML。

Q: Dots 与 Muse、GrokBot、Instinct 相比区别在哪？
A: 他归纳为两点：第一是能力最强的 Agent，第二是最安全、最值得信赖的 Agent。确定以这两点为目标后，思路一下就清楚了，能很明确地做出很多决策。换言之，Dots 的差异化不是界面花样，而是把「最强能力」和「最可信赖」同时作为产品最高目标，其他设计取舍都围绕这两点展开。

Q: 你早期测试感觉它一直在征求授权，这种平衡怎么找？
A: 他解释，他们希望大家把很难、也意味着很大责任的任务交给它（比如合并 PR、评估硬件、策划发布），所以起步阶段刻意保守，在能力、功能、推出方式上做取舍后再逐步放开。他也感谢受访者参与早期测试，说正因收到「买鞋前还要先同意零售商服务条款」这类反馈，他们讨论后大幅减少了所谓「过度确认」——有些事其实不用再问，也能放心让它做。

Q: 大家担心 Agent 会搞黑客攻击、不愿交个人数据，你们怎么处理？
A: 他强调很高兴整个市场都在讨论「到底把多大责任交给 Agent」，这对他们有利，因为在这款产品上非常认真对待。他澄清所披露事件用的是原本不打算内部发布的模型，且当时沙箱隔离和防护也未达到产品水平，而 GPT-6 Astra 对齐非常好、产品里内置了很多层安全机制。架构上则是：模型本身对齐 + Codex Harness 运行 + 修改 Harness 支持持续运行与子 Agent，并重新评估安全性。

Q: 产品里有哪些控制机制保证规则被执行？
A: 他分了三个方面。第一是默认行为与可自定义规则——默认指示模型主动用你接入的工具做研究、琢磨怎么帮你，但确认前不采取行动；你也可以设「我在度假时告诉来问的同事我在休假」这类规则。第二是执行保障，有一层「自动审核」，用另一个模型监督负责执行的模型，它知道你设的规则和自定义指令，确保一切正常。第三是操作可追溯：无论你在产品里做的事，还是模型做的事，你都能查看它运行了哪些子 Agent、这些子 Agent 在干什么。

Q: iMessage、WhatsApp 什么时候能用上它？
A: 他表示当然希望「你在哪里工作、哪里沟通，就能在哪里用」，不光是工作也包括个人日常生活。短信功能「很快就会推出」，为实现它经历的那些事改天可以当趣事聊，但现在只能说快了，其他还不能多透露。这与产品的整体方向一致——让 Dot 成为一个跨工具、跨场景都能联系到的独立身份，而不是被锁在单一应用里。

Q: Dot 的用量不计入套餐限额，这是永久的吗？
A: 是永久的。他解释这是新的定价方式，核心是「让你不会用光额度」——用着用着不能用了体验很糟，而且若你指望它替你盯航班、看路况、到点叫 Uber，结果前一晚写代码用太多它就不干活，这绝不可接受。原则是 Dot 全天候随时可用（滥用除外）、随时都能很快回复，额度与主 Codex 额度分开，接下来这个月额度会很充裕，边搭机制边观察再调整。

Q: 免费用户最终能用上这些能力吗？Chat 和 Dots 如何共存？
A: 他说 Chat 肯定会一直保留，它是增长最快、面向普通用户的助手，用户超 12 亿；另有 Agent 产品 Codex 和 Work，合计 3500 万用户、仍在增长。他认为 Work 其实应直接合并到 Chat 里，会这么做。Dots 沿用 Codex 的路线——把前沿能力以谨慎保守又强大的方式先推给 Pro 用户，再让 Plus 用上，最终让免费用户也能用，方式就是把这些能力融入 Chat，让它直接升级，而不要求 12 亿人改变现有习惯。

Q: 一年后再聊，你期待最有意义的变化是什么？
A: 他希望把之前谨慎压着没做的事做出来：让更多用户（不再只限 Pro）用上；让 Dot 能跟其他人甚至其他 Dot 交流（这件事要考虑得非常周全谨慎）；打磨 Dot 与 Space、本地 Codex 的配合。他还提到一个尚未聊到的方向——专门负责某项工作的 Dot：助手型 Dot 是个人延伸，而组织若有某项职能或工作流程想提高自动化，可能希望创建由 IT 统一管理、有独立于任何个人身份的专职 Dot，这块起步很慢、只跟少数客户合作。

Q: 你的 Dot 帮你做过最不可思议的事是什么？
A: 他讲了一个产品推出准备期间的故事：一位一起工作的工程师一觉醒来，发现 Slack 里收到好多表扬嘉奖——因为他的 Dot 在一个 bug 进入生产环境前就修好了。这位工程师让 Dot 持续关注反馈频道，Dot 发现一个问题并创建了 PR；他没把 PR 设成草稿，而 Dot 摸清了他「总是直接创建 PR、总是设成自动合并」的个人习惯，于是也设了自动合并，后来有人批准就合并了。他坦承讲这故事有点犹豫，因为你不希望这事在当事人不知情下发生，所以正针对这种情况做很多安全管控，这也是要小规模做的原因。

Q: 关于「两年后算成功」，Greg 给了你什么有趣的回应？
A: 他回忆刚加入时开了个会，Greg 也在场。Greg 问团队有没有人想提问，结果没人提问，大家都紧张，而他是公司 CEO，大家就看着他。他硬着头皮问「那两年后做到什么样算是成功」，Greg 看着他说「两年后那也太久了，你问的时间跨度不合适，你应该问两个月后做到什么样才算成功」。他当时心想「天哪，我这就被开除了」。这段插曲也说明在 OpenAI 变化太快，六个月前都想不到现在的样子。
