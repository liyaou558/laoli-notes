## 一、核心观点

### 1. Personal Agent 是主线延续，不是一次「乍现」的爆点

曲凯把这一波放进更长的时间轴里看：它是 Openclaw 那一波的延续，而 Openclaw 又是 Manus、乃至 2023 年以来「用 AI 做事情」的延续，最后 agent 和 AI coding 也都合到了同一条线上。子皓不认为这是爆线：「对于我们来说，不算炸线。这一波的 Personal Agent，我觉得是满足了很多我们算是上个时代活下来的产品经理能够看到的端倪——这是一个能够持续很久的事情。」他判断像 Muse、Grok Bot 这类产品已经具备了「让普通人用」的全部要点：你不需要知道任何技术细节，上来就能用。正因为底层智能已经足够，真正被卡住的不是模型，而是「人跟 AI 的交互方式」，这决定了这波能走多远。

### 2. 需求的本质是「获取智能的成本」，而不是「智能有多强」

这是本期最底层的一条论证。子皓打了个比方：现在每个人每天用智能两三个小时，「这个是这个世界最大的不合理」——我们已经达到了智能平权，却没有像用空气和水电煤一样去用它。真正改变需求的变量是获取智能的交互成本。「如果你能够张嘴一说，它就能帮你做，那么大家觉得默认智能可以帮你做任何事情，那其实可能每个人都会用很多。但现在不是这个样子——你需要首先让它满足很多东西，先做很多 set up，然后你去跟它解释。」他把它类比成电量焦虑和增程汽车：「可能你 100 天都不会用到一次增程，但你但凡用了一次你就很痛，那么你 24 小时里如果获取智能的成本很低，为什么不呢？」一旦行为的成本趋近于零，需求就会急剧放大——这是静态看需求的人最容易忽略的地方。

### 3. 成本不是核心矛盾：真正在意的是「成本 / 速度 / 智能」的再平衡

曲凯问 Personal Agent 是不是特别烧钱，子皓的回答绕开了成本焦虑：从供给角度看，「没人 care 到底后面用了什么模型」；像订餐厅、订票这类任务，本身不在智能层面有多高体现，用户对延迟（响应速度）也没那么苛刻，所以速度是可以被放弃一点的。对做产品的人来说，真正要做的是在帕里托曲线上找自己的点：成本、速度、智能三者的下一个平衡；「我们本身在意的是，不希望因为成本去阉割任何用户的体验」。换句话说，模型能力「确实差不多了」，胜负手不在算力军备，而在如何把能力低成本、低摩擦地交付到人手里。

### 4. AI Coworker 慢，是因为被组织的「最窄水管」卡住

谈到为什么 cowork / To B 方向没有想象中发展得快，子皓给了一个结构性解释：它在组织中的应用涉及非常多组织内部的变革，「你就像是一个大的水管，会被水管里最窄的那一段给限制住」。他观察到几乎没有大公司能靠 Ai Native 转型成功，但重新建一个公司，效率高 5 倍以上。他类比电的发明：「电发明之后，按照使用电的方式去建一个工厂，可能需要 30 年」——旧组织的淘汰换血是渐进的，直到用新方式长出来的公司越来越多，市场价格才会被推高。所以创业公司扎堆做 To B 在他看来是「看硅谷看多了，有点魔怔了」：在那个时代 To B 渗透率已经很高、冒头就被抄，你干嘛还要走老时代的路。

### 5. Personal AI 天然不带网络效应，但 A2A 可能带来

子皓引用 Peter Thiel 的壁垒框架，坦率承认「Personal AI 这个名字天然的就不带网络效应」，因为一个人的 personal 东西只属于自己。但他相信 agent 之间（A2A）具备网络效应可行性，而且因果链条是反的：「不是因为可以 A2A 所以才有你的产品，而是因为用了你的产品才有 A2A。」因为用了你的产品，你才有我的 memory、我的 file system、我的所有沉淀，这些东西天然属于你自己；而人和人连接需要的恰恰是别人脑子里的 knowledge 和时间。他举了自己公司的真实案例：好几个 Lark 群里同时有他本人和「他的 bot」，同事们从不跟他说话，而是直接 @ 他的 bot 帮忙审稿、看方向——「我的 bot 来把他们看这个东西对不对，或者这个方向按照子皓的理解是什么。这天然就是一个 A2A 的场景，我受解决的只是权限问题。」

### 6. 四款竞品点评：Town、Grok Bot、Muse、Instinct

子皓对海外产品逐个拆解，观点锋利。**Town**：「有一点外观点的痕迹」，CEO 是某知名金融/支付公司的 CTO，产品特别注重权限和 reference，connector 设计明确，很符合许多 To B 场景，也做了 A2A，最大用户群体之一是家长（学校不停地通知夏令营、报班、作业）；但他觉得产品信息架构「没有中国人做得好」、A2A 特别复杂、对智能的使用不高，「不在智能长线上」，长期不太看好。**Grok Bot**：他认为是非常好的产品，做授权、透传、稳定虚拟机做得好——有些 bot 用 MCP 或接口接不上，它就给你起一个浏览器，输邮件密码时弹窗让你输，对普通人更安全；bot 之间的 context share 也做得好，加上是 Cursor 团队及其增长负责人做的，细节和传播方式都很讲究。**Muse**（Meta）：有明显「移动互联网时代」的烙印，非常精细、花了很多钱，每个人上来送一亿 token，「你第一天用它就觉得这真的是一路浪浪时代定义的好产品」；它有 go 和长目标（长程任务）功能，判断普通人对长程任务的定义会和程序员不同，往普通人方向比 Grok Bot 走得更远。**Instinct**：主打订机票、订酒店、订餐馆，子皓认为这类「好描述的案例」本质上是解决 Openclaw「案例难描述、描述完也难用」的传播问题——「现在下个 App 我还要花钱，现在免费，省了 499」，典型的老互联网式传播。

### 7. 交互是最大的机会，也是最被低估的战场

被问到「什么是非共识」，子皓答得干脆：交互。他对 AI 眼镜的体验特别难受——你看到一个东西、听到一句话，想让它帮忙，得先唤醒（「Hey Meta」），再把刚才的事重复一遍，再说出要求；「那个重复一直让我觉得很奇怪，它明明就戴在我的脸上，明明就能听到」。重复的根源就在于它「不是一直在跑、不是跟空气一样默认围着我在跑」。他引用《Her》和《钢铁侠》——从没见过里面的 AI 需要你复述一遍，电视剧也不这么拍。他还复述乔布斯当年说服员工的故事：「以后每个人每天都会用电脑，每个人都要等 30 秒，如果你能把它变成 3 秒，你就帮全世界省下了多少寿命。」对应到 Personal Agent：「可以预见半年之内，至少平均每个人每天会跟 Personal Agent 说三十句话。」这正是 Ambi 要做的事——AI 一直在后台跑、在现场，而不是异步的 human in the loop。

### 8. 硬件的三点结构性优势，与「不做端侧大模型」的物理约束

子皓总结硬件相对软件的三点优势：**其一**，硬件的获客渠道本身不具备特别强的网络效应，但一旦建立渠道就能形成优势——「像安克、大疆，它出了新品就能铺出去」；相比之下软件在抖音不建账户、不投广告就卖不出去。**其二**，硬件有独占性：软件我可能同时开 5 个，但人身上只会带一个，「买都买了」的情况下，你在上面附加消费的价值在 AI 时代会被放得很高。**其三**，软件的用法逻辑相反：100 个功能里 98 分钟好用、2 分钟难用，你可以把那 2 分钟换成别的软件拼起来用；而硬件同一时刻只能做一件事，「每天 100 分钟里那 2 分钟特别恶心，就是我每天 100% 要吃那两分钟的屎」。所以那些「每天用的场景不多、但每天必然发生」的需求一定要满足。至于端侧模型，他的取舍来自物理规律：「现在并不是算力受限，更多是电池受限」，本体质（form factor）决定了 Ambi 没有选择任何端侧大模型。

### 9. 应用公司不必自己训更强的模型，但要会「优化」

子皓引用一位红杉合伙人的观点说清这件事：模型公司提供的几种接口，是帕里托最优化曲线上的几个点；对不同的应用公司来说，成本、速度、智能本身可能是曲线上的别的点，去优化这些点并不是追求更高智能，而是做更好的平衡——「说白了就是跟你去优化代码一样，把模型的效率优化好，让你的 ROI 做得更高」，在这个维度上训模型/优模型是合理的。但他认为训练一个「智能程度更高」的模型很荒谬：「你去跟两万亿的（AI lab）拼，一个是卡的问题，另一个是你到底有什么样的数据，能够代表比现有模型更高维度的智能。」他自嘲：「我何德何能，能够让 Claude 来争取我？我到底知道啥他们不知道的东西？」

### 10. 从溜冰票独家代理到消费硬件：一位「总能赚到钱」的 founder 的认知路径

曲凯把子皓的履历拆成几段。**第一段（公益创业 6 年，融三轮，最后被收购、钱退回）** 带来的最大认知是：timing 和赛道比能力、比所有事情都重要，「选择比努力更重要，而命运或者大的浪潮比选择更重要」。**第二段（保险、创新支付、To B SaaS 共 4 年）** 让他理解了商业模式的本质：「其实都是很简单的事情，所谓的商业没有什么秘密」——他做过六七种不同商业模式，每种都能做到全国前三前二，而底层都是效率、ROI 和需求。**第三段（模型公司 + 消费硬件公司）** 补全了硬件研发、仓储与设计：「2B 软件属于你要多试错，找到好地方就 double down；2B 交付在于签单那一刻你的收入就已经 capped 了，后面是交付得更好、成本更低。做硬件也是第一天就决定后面所有的风险。」他还原了硬件传统的 go-to-market 三年流程：Kickstarter 测试 → 找媒体 → 上独立站 → 上亚马逊 → go global。他认为眼下 AI 时代的机会，就是拿 coding agent 去回头重构这些业务构成和组织形态——「一年时间希望做别人三年做的事情」。

## 二、关键问答

**Q：为什么最近 Personal Agent 这么火？它是像 Openclaw 那样的爆线吗？**
A：曲凯把它定位成主线延续——从 Openclaw、Manus 到 AI coding，都是「用 AI 做事情」的延续。子皓不认为是爆线，反而觉得这是很多「上个时代活下来的产品经理」早能看到的端倪：这是一个能持续很久的事，因为像 Muse、Grok Bot 已经具备了让普通人用的全部要点，你不需要知道任何技术细节。

**Q：去年你们的判断是「智能已经足够了」，现在看错了吗？**
A：子皓承认可能想错了：智能平权已经达到，但「每个人每天用两三个小时」是这个世界最大的不合理。模型能力「确实差不多了」，但真正没被解决的是人机交互——大家没有像用空气、水电煤一样去使用智能，所以补的不是智能，而是获取智能的方式。

**Q：Personal Agent 的成本是不是一个大问题？**
A：不是核心问题。子皓认为从供给角度看没人 care 背后用什么模型；订餐厅、订票这类任务对延迟不苛刻，速度可以放弃一点。产品真正要做的是在成本、速度、智能三者之间找下一个平衡，而不是为了成本去阉割用户体验。至少对这个赛道而言，商业模式是成立的。

**Q：人们对 Personal Agent 到底有多大需求？**
A：恰恰取决于「获取智能的成本」。子皓说这是比需求更底层的问题——如果张嘴就能用、成本趋零，需求会急剧放大；现在要 set up、要解释，交互成本高，那些生活里的鸡毛蒜皮就很难被触发。他用增程汽车和电量焦虑作比：用得少但一旦需要就很痛，所以只要成本低，24 小时都在线才是常态。

**Q：为什么 AI Coworker / To B 没有想象中发展快？**
A：组织变革被「最窄的水管」限制。子皓说几乎没有大公司能靠 Ai Native 转型成功，而重新建一家公司效率高 5 倍以上。他类比电的发明——按用电方式重建工厂要 30 年。所以创业公司扎堆做 To B，在他看来是「看硅谷看多了有点魔怔」：那个时代 To B 渗透率已很高，冒头就被抄。

**Q：Personal Agent 会不会还是大厂的机会？**
A：子皓承认强网络效应的上游会限制独立性，中国的分发环境确实对大厂有利；但他强调要看海外市场，线下的硬件并不具备封闭的社交网络和强网络效应，所以独立公司有机会——这也正是他们选择做软硬结合（Ambi）的原因之一：不在大厂的渠道和分发半径里被压榨。

**Q：Personal Agent 天然不带网络效应，那壁垒在哪里？**
A：他引用 Peter Thiel 的框架，承认名字上就没有网络效应，但相信 A2A 可以带来：因果是反的——因为用了你的产品才有 A2A，因为你有我的 memory、file system 和沉淀。人连接人需要的是别人脑子里的 knowledge 和时间，agent 之间共享这些 personal 内容，就能给双方带来正向外溢，因此「A2A 是先有网络效应的」。

**Q：你怎么看 Town？**
A：子皓认为它有「外观点」的痕迹：CEO 是知名金融/支付公司的 CTO，产品非常注重权限和 reference，connector 与权限设计明确，符合很多 To B 场景，邮件自动打标签/归类/写草稿，最大用户群之一是家长。但他觉得产品信息架构「没有中国人做得好」，A2A 特别复杂，对智能的使用不高、不在智能长线上，所以长期不太看好。

**Q：Grok Bot 和 Muse 呢？**
A：Grok Bot 是很优秀的产品：授权、透传、稳定的虚拟机做得好，接不上接口时给你起浏览器、输密码时弹窗让你输入，对普通人更安全，bot 之间的 context share 也强，加上是 Cursor 团队和它的增长负责人做的，细节与传播方式都好。Muse 有很强的「移动互联网时代」烙印，精细打磨、花钱多，每人送一亿 token，还有 go 和长目标功能，往普通人方向比 Grok Bot 走得更远。

**Q：你们怎么和 Muse 这样的对手 PK？**
A：Ambi 的定位是软硬结合，和它们在两点上不一样：一是增加线下的 context，二是提供线下的交互入口——「这是最重要的一点」。子皓说他们半年前就预测到了这个 gap：现在所有 Personal Agent 都缺线下 context 和线下入口，每次用它都要花 30 秒到 5 分钟。他们希望 AI 跟人的关系是「在场」而不是异步的，不要 human in the loop。

**Q：你怎么看应用公司自己训模型这件事？**
A：子皓用红杉合伙人的观点解释：模型给的是帕里托曲线上几个点，应用公司去优化成本/速度/智能的另一个平衡是合理的，本质是「优化代码、把 ROI 做得更高」；但训一个智能更高的模型很荒谬——跟两万亿的 AI lab 拼卡、拼数据维度没意义。所以 Ambi 没有选择端侧大模型，因为「更多是电池受限，不是算力受限」。

**Q：这波 Personal Agent 最大的机会来自什么？**
A：子皓的答案还是交互——人跟 AI 的交互方式。大家对 AI 最好的想象就是「言出法随」：一是你张嘴说，二是它能做好。因为底层交互没发生最大改变，大家才觉得生活场景没需求；一旦行为的成本变成零，需求会急剧放大。他强调不能静态看这个问题。

**Q：很多产品的 Proactive 是不是做错了？**
A：是。子皓认为主动性必须有成本、有明确的 input，否则就像「一个秘书每半小时敲门问一下」，一天进二十次只有一次「提得好」，账根本算不过来。他们的主动性不是机械的 delta 触发，而是来源于环境的变化——要有线下 context 变化产生明确的 input。

**Q：Personal Agent 有必要区分工作和生活场景吗？**
A：子皓认为不应该分开：工作和生活的 context 一起给 AI，才能更了解你、提供更好的价值；区分对智能本身不麻烦，是信息架构问题。另一个非共识是他们不做 persona——「为什么 AI 一定要是一个跟你不相关的客体」，他们选择让 AI 成为你自己的延伸、你主体的一部分，「外人来找的是曲老师的助手，还是曲老师的延伸」，认知完全不同，后者更可能做成网络效应。

**Q：现在已经到了能跑出亿万级用户产品的 timing 吗？**
A：是的。子皓判断当「所有能被数字化的任务，成功率趋近 100%」之后，水电煤式的基建就完备了，上面就能长出五花八门的东西。他引用一条评论——一个不 care 模型，另一个是基础能力（指令追随、工具调用、强化学习做长程任务）都到位了——日常任务都能被虚拟化完成，「就点到它上线了」。

**Q：为什么国内跑出来的 AI 产品这么少？**
A：这是本期唯一没有答案的开放问题。曲凯说他第一次见这种状况：已经 9 月底、发出来都 10 月了，今年中国让人眼前一亮、大家都知道的产品几乎没有，大厂也没有。子皓也认同，甚至说「中国人做的比 Granola 好的产品都没有」——他觉得这很奇怪，也没能给出解释，只希望局面能很快变化。

## 三、备忘

**人物与机构**
