## 一、核心观点

### 模型在榜单上接近满分，商家在真实经营里却「没感觉」

张阔点出了这期节目最扎眼的一个落差：现在每次新模型发布，各种通用评测（coding、数学、agentic 能力）动辄打到 99 分甚至 99 点几，但团队在日常经营里使用时，并没有感受到同样幅度的提升。他的结论是——「通用智能水平变好」和「在电商领域能完成更多工作」这两件事的相关性并没有那么大：通用能力提升确实能让某些工作的通过率更高，但本质水位并没有被每一次发布拉得那么开。为此，团队基于阿里国际站与 Accio 里上百万条真实经营、问答数据，整理出一套 107 个任务的评测集，测试 AI 在**完全无人干预**的情况下能不能把活干完，结果最前沿模型的通过率只有约 61.7%——高到足以证明有用，低到足以令人警醒。

### Coding 的 AI 渗透率已到 99%，商务/电商 Agent 才刚刚开始

张阔给了一个鲜明对比：Agent 最早解决的是 coding，如今 coding 的市场渗透率他估计有 99%——很难找到身边一个完全不用 AI 写代码的研发，绝大多数代码已由 AI 产生；而第二个垂直赛道的渗透率远远小于这个数字。原因在于 coding 100% 数字化、且天然可验证（能不能编译、结果对不对），天生适合现代大模型；而商业场景数据更多元、没有通用流程、不同企业对「结果好坏」的判断有直接差异，验证周期还要按天、按周、按月甚至按年去记，整个反馈闭环极长。所以像电商这种需要复杂判断、长程任务、结果又不是当下可验证的场景，Agent 只是刚刚开始的阶段。

### Accio Work：把「搜索一个关键词」延展成完整的 agentic trade

张阔回顾了产品演进：一年前 Accio 核心解决的是 AI 搜索问题，让买家能用自然语言或多模态描述需求——现在整体搜索涨 20%，**多模态搜索涨 130%**，用户描述需求的方式和值钱相比已有很大差别。第二个阶段，sourcing 本身向前向后延展：向前要做市场调研、做产品 design pack 设计，有了设计再对接供应商推进沟通，直至完成交易，也就是 agentic trade（AI 驱动交易）。到今年 4 月推出 Accio Work，希望解决的问题进一步泛化——它基于 alibaba.com 和 1688（全球最大的供应链平台），能帮用户用一站式服务管理所有电商后台、理解多平台经营情况、管理供应链，甚至管理员工在日常经营里的表现。

### 案例：一个植物监测的「想法」如何被 AI 在 24 小时内推成生意

张阔在 CoCreate 大会上讲了商家 Adward 的例子：他爱种植物却总把花养死，于是想做一个能让植物「告诉」主人自己状态的消费级电子监测产品。从 idea 到 design pack，从确定用什么检测/读取设备、如何压成本做出 margin，到找到广州、深圳最厉害的电子厂商制造，再到订船期、过海关用哪个 HS code、管理物流，最后生产社媒内容、在 Amazon/eBay/Shopify/TikTok 多店销售、应对不同平台规则与定价、管理买家反馈并持续迭代——Accio Work 可以把这整条周期在一个 Agent 里跨端完成。过去商家要维护一张 20 列、十几个供应商的 Excel 去比产能、资质、工厂水平、拿货价、涨期、物流方案，back-and-forth 以「月」计才能拿到样品；现在 AI 可以把这个周期缩短到以「天」计，24 小时之内就给出一份结果报表。供应商反馈说，从没见过这么专业的 design pack。

### 通用模型越强，垂直产品的优势反而更清晰

面对「底层模型越来越强，为什么垂直 Agent 还有机会」的问题，张阔的答案是 agent = model × harness × context 的**乘法关系**：任何一项为零，整个结果就是零。所以不能只优化模型、指望用一个通用 frontier 模型加几句 prompt 就交付结果，而要在训练、serving、harness 三处同时精细打磨。他特别强调 model 与 harness 必须**联合优化**——不是模型升级了就直接换通用模型跑。而 context（日常经营上下文、平台集成、供应商沟通、行业趋势）正是阿里积累了二十多年的优势。由此垂直赛道的竞争变成一个多元化、全方位的竞争，这也是不同垂直领域的 Agent 能真正跑出来的原因。

### 「用得起的 AI 才是有价值的 AI」：多模型路由把成本压到约三分之一

因为要服务的是**日常经营**、而非一次性解一道数学题，成本成为硬约束。张阔说商家侧的感受是必须便宜。做法是「帕累托最优」式路由：把 L3 以下的简单工作交给小尺寸、高性价比模型，复杂困难的问题才路由到 frontier 模型；用户也可以直接选 auto 模型让系统自动优化。在同样跑完 107 个任务的对比里，Accio Work 的估算成本是 3.69 美元，而 Codex 和 Claude Code 都在 9 美元以上——约为其余两家的三分之一。他还提到，用最新版本的小尺寸千问模型做后训练（post-train），效果已非常接近 frontier 顶级模型，于是大量简单工作就能被更快、更省地完成。

### 专业垂直 Benchmark 正在变成基础设施，但必须持续 eval 防「腐化」

张阔认为，越来越多模型公司需要具体领域的数据来训练，所以专业领域 Benchmark 变得非常重要、数据公司很火。阿里把 CommerceAgentBench 在 GitHub 开源，含 107 个端到端任务（覆盖七大类、L1 到 L4 难度），希望所有模型在训练和评测时都围绕它做，这样「每次出来可以借大家的光」，否则各家评测口径不一，模型进来还要做大量适配。一个更关键的点是：模型或 Agent 迭代一段时间后可能出现「腐化」——原来的 case 变得不行、结果更差，这是不可接受的，所以每一个版本都要持续 eval。他也因此给了一个商业上的 AGI 定义：在给定 budget 和供应链不变的情况下，Agent 一定比一个人做日常操作与判断赚到更多的钱，那就是商业领域里的 AGI。

### 人必须保留的判断：下单按钮、产品品味与市场判断

张阔反复强调，不是按环节去切「哪些给 AI、哪些给人」，而是按性质：**一定需要人做决策、且要为经营结果负责的事情留给人**。比如要不要支付、要不要采购这批货，这个按钮一定交给人。更上游的，一个 idea 靠不靠谱、面对的是不是一个愿意支付足够溢价的客户群体、产品的 taste、此时此刻对市场的预测与判断、同一个 budget 是投更多广告还是备更多库存、是铺更多渠道还是要更大 margin——这些都是老板本人对一盘生意的判断。AI 可以帮做大量市场分析、调研、竞对判断，但最终的商业判断还是要人去做。

### Agent 的三种「长程」范式：「上云」是基础需求，「不挂」本身没有意义

关于「24 小时在线、持续响应」，张阔把两个概念拆开：上云是个简单的事，Accio Work 的 PC 版之后几天就有了云端，因为本地 memory 放云端就能换台机器继续操作——今天一个 Agent 说没上云，只能说功能还没做完，这不是技术上的大差别。而「长程」是另一个概念，且要定义「多长程、在什么场景、完成什么目标」。他把经营中的长程任务分成三种范式：**定时任务**（每天出店铺经营报告、看员工工作好坏）、**事件驱动任务**（多供应商沟通中基于新信息推动结果）、以及**季度/更长的经营长程任务**（一盘生意赚没赚钱、要复盘什么）。他不认同只追求「模型跑 7×24 小时不挂」——如果不解决你的问题，「不挂 means nothing」。

### 中美差异：SaaS 生态 vs 平台整合，以及第一天生来就是全球产品

聊到中美 Agent 生态，张阔认为从「办公」角度差异反而较小，但底层延续性不同：美国垂直 SaaS 生态成熟（CRM、广告、律师、医疗各有成熟的垂直 SaaS），中国则更多是平台侧把大量垂直功能整合进去，所以 AI 进来时也带着惯性差异。落到电商：美国有 Shopify、独立站的生意且持续增长，中国商家第一想法不是做独立站，淘宝天猫本身是「平台 + 集成大量工具」的中间态——但最终给客户交付的价值项是一样的，只是形态不同。有意思的是，AI 产品第一天就是全球的：Accio 从一开始就能做一个全球平台的产品，没有语言问题、交互门槛也普遍降低，这可能是 Agent 时代一个新的产品设计范式。

## 二、关键问答

**Q：你怎么判断「AI 同事 / Cowork」这个市场？**
A：Agent 最早解决 coding，coding 的渗透率估计有 99%，身边几乎找不到不用 AI 写代码的研发。相比之下第二个垂直赛道渗透率小得多，因为 Cowork 本身偏 work 类，能交付的内容还比较有限，多是文案类、计算类工作。对电商这种要复杂判断、长程任务、结果又不是当下可验证的场景，整个 Agent 还处在刚刚开始的状态。

**Q：为什么 coding 交给 Agent 更容易，商务类更难？**
A：一是 coding 100% 数字化，所有代码在 GitHub、codebase 里容易被 AI 广泛学习；二是它天然可验证——能不能编译、结果对不对，天生适合大模型。商业场景则数据更多元、没有通用流程、不同企业对结果好坏判断不同，验证还要按天/周/月/年去记，反馈闭环周期很长。

**Q：Claude Cowork 这类通用 Agent 出来之后，这半年有什么变化？**
A：第一，赛道更热闹了，在国内进任何一个电梯间看到最多的产品就是各类通用办公 Agent。第二，各家有自己的特色；Accio Work 的核心还是解决电商这个垂直人群的问题，且能解决的问题比一年前更泛化——从单纯的 AI 搜索，延展到 sourcing 前后完整路径与 agentic trade。

**Q：Accio Work 现在能接管卖家的哪些环节？**
A：它基于 alibaba.com 和 1688，可以帮用户用一站式服务管理所有电商后台，理解多平台经营情况、管理供应链，甚至管理员工日常经营表现。用户既可能在 1688 进货到淘宝、天猫、京东、抖音卖，也可能在 alibaba.com 进货到 Amazon、Shopify、eBay 等全球平台卖。跨端管理「一本生意」是它现在能做的。

**Q：跨境商家的具体使用流程是什么样的？**
A：以 Adward 的植物监测产品为例：Accio Work 先帮你把 idea 做成 design pack，帮你找到广州、深圳最擅长电子产品的厂商制造，再帮你解决订船期、过海关用哪个 HS code、到港后的物流管理，最后还要生成各平台 social 内容、在多店按不同规则和定价销售、管理买家反馈并持续迭代。整条周期在一个 Agent 里跨端完成。

**Q：这个过程里，哪些步骤还需要人来做？**
A：需要商家做「选择」——知道哪个方案更好，这是人和 Agent 合作的步骤。更根本的是，最初没有 Agent 时，你要从关键词开始，维护一张 20 列、十几个供应商的 Excel，比较制造能力、资质、工厂水平、拿货价、涨期、物流方案；有 Agent 后，把它分解成可制造的产品、匹配商家、在授权下替你与多个商家沟通、拿到报表，把「以月计」的周期缩短到「以天计」，24 小时内给结果。

**Q：中美 Agent 生态有什么差异？**
A：从办公角度差异较小，但延续性不同。美国垂直 SaaS 生态成熟——CRM、广告、律师、医疗各有成熟的垂直 SaaS；中国更多是平台侧整合了大量垂直功能。但最终要给用户交付结果这一点，各平台想做的一样。

**Q：AI 会替代 SaaS 公司吗？**
A：如果 SaaS 本身做得很简单，AI 确实会削弱它的部分能力。但 SaaS 与工作流集成紧密，理解企业上下文（也就是现在流行的 ontology，即各数据对企业到底意味着什么）是它的优势；反过来 AI 进企业也一定要理解这盘生意。所以现在是两边互相集成、互相升级的过程，而不是单向替代。

**Q：美国的法律、医疗 Agent（如 Harvey、Open Evidence）是 SaaS 转型还是 AI native？**
A：这些更多是 AI native 的 Agent 产品。每一个时代都有那个时代的公司——有些人对技术理解更好，同时对经营领域理解更深，速度就更快。就像移动互联网时代会冒出移动互联网时代的产品，每个技术转折节点都会有新公司出现。

**Q：你们在海外和国内出不同版本吗？**
A：AI 产品第一天就是 global 的，天生没有语言问题，各地要解决的交互问题大同小异，交互门槛还比之前普遍降低（虽然有一部分 GUI 属性，大部分用户用自然语言描述工作即可交付）。真正有差别的是 agent = model × harness × context 里的 harness 和 context：美国要接的工具、平台与中国不同，context 又跟日常经营上下文、平台集成情况（供应商对话、商业数据、行业趋势）有关。

**Q：model、harness、context 三项里，你们投入哪一项更多？**
A：现在是齐头并进的。最开始大家在 harness 上花精力更多，因为要连工具、管 memory、做授权，保证系统持续运行；电商天生是长程任务，要连续几个月执行经营，harness 本身就要花很多精力。context 是阿里二十多年积累的天然优势。现在 model 也花很多时间，因为 model 和 harness 要联合优化，不是只优化一个、另一个用通用 frontier 模型就行——训练、serving、harness 三处都要精细打磨才能拿到最好效果。

**Q：模型都这么强了，垂直产品的优势是更明显还是变了？**
A：我们对这件事的理解也在迭代。为衡量 Agent 好不好，我们自己做了 benchmark。因为通用能力得分高和电商领域能完成更多工作相关性并不大，所以我们用上百万条真实数据总结出 107 个任务并开源，配合 Accio 作为统一 harness 去评测各模型。现在最 frontier 的模型在这个 bench 下通过率只有 61% 多一点，想达到及格都有点费劲。

**Q：你们做的 Benchmark 是什么？为什么重要？**
A：107 个任务是真实经营数据的 stepshot（快照），分七大类、L1 到 L4 难度，越长程、结果越开放的任务能通过的模型越少。把它放到一起形成新的帕累托最优曲线，帮用户在最低成本下拿到最好结果。我们开放是希望各模型训练时围绕它评测，否则各家口径不一、进来还要做大量适配。而且模型或 Agent 迭代后可能「腐化」，所以每个版本都要持续 eval，保证测试结果和真实经营结果一致。

**Q：107 个任务具体是什么类型？**
A：都是日常经常会碰到、跟电商或平台相关的。比如买家给商家发 quotation，要从大量回复里选出最合适供应商，还要识别里面掺杂的钓鱼邮件，把从工厂价到含税到手价算清楚（任何一步 fail 或算错就算没完成）；比如给定交期到指定港，要在船公司网站成功 book 到船才算完成；比如平台大量 dispute，要判断基于现有信息结论是不是「赔/不赔、对不对」，还是要更多信息。有监测计算结果的、有监测能否执行成功的、也有监测商业判断的，涵盖七大类。

**Q：哪些环节对商家更难、哪些人更愿意自己操作？**
A：不会按环节那么分。一定需要人决策、要为经营结果负责的事留给人，比如支付、采购这批货的按钮一定交给人。按频次看更有意义：第一大类是多平台经营——有流水不代表有利润，跨多个平台看投入、收益、退换货，以前要来回切换、整理 Excel 还不一定算对，现在 AI 很容易；第二类是发布商品——多平台规则、受众、媒体形式都有差别，统一 update、大促打折这些重复工作交给 AI 很方便；第三类是客服经营与 2B 客户预警，AI 能快速分析所有经营结果，提前预警可能出问题的单子。

**Q：AI 变强后，商家的预期是不是更高、更复杂了？**
A：一定是这样。每天分析 Accio Work 里七大类、L1 到 L4 的任务，从发布第一天到今天做截图会发现，任务难度不断从简单退到复杂：一开始大家只是 L1 级问问题要答案，慢慢变成「我交给你任务，你帮我做完」，再到给更复杂、跟经营最终判断相关的任务。商家每过一段时间一定会 push 产品去解决更复杂的问题。

**Q：最贵的模型不一定最好，你们怎么把成本做低？**
A：因为要服务日常经营、而非一次性解题，必须便宜。我们用帕累托最优模式路由：L3 以下用高性价比小模型，对多模态、视频要求强的才路由到特定模型。选择 auto 模型可由我们帮你优化。同时同等模型下，我们在 harness 工程实践和 context 管理上效率更高。所以同样通过率，Accio Work 成本约 3.69 美元，Codex、Claude Code 都在 9 美元以上，约为三分之一。

**Q：你们支持哪些底层模型？GPT-6 Astra 发布会影响你们吗？**
A：基本上你能看到的都支持；但帕累托最优曲线已经完全埋在下方的模型就没必要支持了。Astra 你们可以过两天直接去我们 bench 上看它的评分。之前常有的问题是：一个模型说它某个事情解决得好，就以为它所有事都能解决好——这俩其实不是相关的（可能它做 3D 不错、在 computer use 上有突破，但不代表通用商业里的 agentic 能力就强）。所以我给你打保票，它肯定不是 AGI，最终还是以最高性价比完成任务为第一优先级。

**Q：垂直产品流程写得太死，会不会限制模型发挥？**
A：不会去固定这些流程。核心标准是先固定「红线是什么」（什么肯定不能做），但路线不是定死的。只要你能把目标说清楚，它一定会不断优化流程、逼近你想要的目标。

**Q：多个 Agent 给的建议冲突，商家该听谁的？**
A：不同 Agent 给不同建议非常正常。最核心的是作为老板，你要有一个整体经营目标，在这个大目标下判断各 Agent 的建议是否合理。商业经营是长周期过程，不是以一次交易成败为目的——这次成交了但最终导致商业失败，那也不是一笔好交易。各平台有各自建议，但你要以自己的核心判断（要毛利、要规模还是要速度）来定，没有统一 Agent 去统一所有意见，这不是产品设计的初衷。

**Q：Agent 上云、「持续在线」具体意味着什么？**
A：要拆成两个概念。上云是简单的事，本地 memory 放云端就能换机器操作，今天 Agent 没上云只能说明功能没做完，不是技术大差别。长程是另一回事，要定义多长程、什么场景、什么目标。商业上可以分几类：定时任务（每天的经营报告、员工绩效）、事件驱动任务（多供应商沟通推动结果）、以及季度才有结果的经营长程任务。我们追求的是打磨这些范式，而不是只追求模型 7×24 小时不挂——「不挂 means nothing」。

**Q：这次在洛杉矶 CoCreate，有什么让你惊讶的？**
A：最惊讶的是人太多了，估计注册到场有 15000 人，前面 booth 太小，一直排队到中午吃饭还没完全进来。美国用户群体在 AI 和 Agent 的教育上确实更领先，对产品理念接受和理解度高；很多客户已经基于这个产品创造并放大了自己的商业。CoCreate Pitch 像 Shark Tank／赢在中国，去年冠军一个英国的 15 岁初中生（做自动帮宠物降温的毛巾系列，年销售额约 100 万英镑），一个美国的 Christian Reid（MIT 毕业，做测量设备，客户包括施耐德电气、SpaceX，今年做到几千万美金以上）。

**Q：小企业怎么借 AI 把生意做大？**
A：全球中小企业是各区域的经济和就业主力，他们原来的核心问题不是「AI 干不干活」，而是没有那么多资源和经验，却想把生意做大、想用全球供应链。今天正好有 AI，加上 alibaba.com、1688 的供应链能力，可以帮更多中小企业从 idea 起步做到更大的商业价值。我们希望通过 AI 进一步降低门槛，让不需要很大公司的中小企业也能把生意做得很大。

**概念**
- Agent 公式：**agent = model × harness × context**（乘法，任一项为零结果为零）。
- ontology（本体）：企业对「各数据到底意味着什么」的理解。
- 帕累托最优曲线：把不同模型放到一起，用最低成本拿最好结果的路由依据。
- 商业 AGI 定义：给定 budget 与供应链，Agent 一定比人做日常操作与判断赚更多钱。
- 长程任务的三种范式：定时任务、事件驱动任务、季度/更长的经营长程任务。
