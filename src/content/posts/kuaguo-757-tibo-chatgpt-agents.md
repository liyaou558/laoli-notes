本期为「跨国串门儿计划」克隆节目 #757，中文声线转述原 Lenny's Podcast 对 OpenAI ChatGPT 与 Codex 负责人 Tibo Sottiaux 的英文访谈，原内容更新时间 2026-10-04。Tibo 谈 Agent 的未来：从一个全天候、会理解目标并持续学习的助手，到 Agent 如何改变产品分发、工作技能以及人与技术的关系。以下内容基于 show notes 与金句整理，非完整转录稿。

## 一、核心观点

1. **互联网上的大部分操作最终会由 Agent 完成。** 这是 Tibo 最直接的一个判断。当 Agent 成为互联网的主要「使用者」，产品团队面对的就不再只是人类点击流，而是一群会实际干活的自动化实体。以 Notion 接入 MCP 后的情况为例，能真正动手完成任务的 Agent 带来了大量流量，团队因此必须重新考虑系统承载能力与商业模式：为人类设计的限额、定价和接口，未必能接住 Agent 带来的访问量。这不是单纯的技术预测，而是对产品形态的逼迫式重构。

2. **未来不必自己编排一堆循环。** 反复设置循环、手动调试工作流，在 Tibo 看来只是一个过渡阶段。他描绘的方向是一个全天候运行、理解目标、记住偏好、并能从反馈中持续学习的 Agent。用户不需要先把每一步该怎么安排想清楚，系统应当围绕「你想达成什么」而不是「你打算怎么做」来组织行为。这意味着交互的重心从命令式编排转向目标式委托。

3. **AI 时代，品味比打字速度更重要。** 他认为「打字快」这项技能的价值正在下降——生成和执行的成本被大幅拉低之后，稀缺的不再是产出速度，而是判断力：理解用户、判断什么才算「好」、并持续迭代。当创造者不必被岗位边界绑死，一个人可以既做设计又做工程时，真正拉开差距的是审美与取舍能力。这会把「专业分工」的默认假设推向模糊。

4. **AI 不该只催人做更多事。** Agent 越多、产出越快，并不自动等于工作更好。Tibo 明确希望 AI 能减少干扰，让人少开一些会、好好休息，把注意力留给真正想做的事，而不是「每秒多发一个 prompt」。这一条像是在给整个「AI 提效」叙事踩刹车：提效的目标应该是给人腾出空间，而不是把人塞进更密的循环里。

5. **他的 Dot 在现场演示前五分钟发现了线上故障。** 在 DevDay 演示开始前五分钟，Dot 发现 ChatGPT 线上系统出了故障，还主动问「要我试着修一下吗」。Tibo 没有让它动手，而是去联系工程团队排查。这个案例同时展现了「环境人工智能」的潜力与边界：它能在人反应过来之前发现异常并主动提议行动，而是否授权、由谁兜底，仍是人的决定。

6. **产品与工作方式都要为「Agent 用户」重新设计。** 当 Agent 成为流量与操作的来源，产品的分发、承载、计费与安全边界都要跟着变。Tibo 从产品发布、团队协作和实际使用场景出发讨论 Agent 如何落地，并强调要为安全与人类需求设计 AI——不是把 Agent 当成一个更快的按钮，而是当成一个需要被理解、被约束、也需要被服务的新型「用户」。

## 二、关键问答

**Q: Tibo 现在在 OpenAI 负责什么？**
A: 他负责 OpenAI 的 ChatGPT 和 Codex，参与推动 Codex、ChatGPT Work 和 Dots 等产品的发展，也长期参与耗时长、持续运行的 Agent 系统与记忆能力研究。他谈论的角度偏向产品发布、团队协作和实际使用场景，而不只是技术路线。

**Q: 这一期最核心的判断是什么？**
A: 是「互联网上的大部分操作，都会由 Agent 来完成」。这不只是技术预测，也意味着产品和工作方式都要重新设计：当 Agent 成为用户，产品该怎么接住它们带来的流量、怎么保证系统承载、又怎么找到商业模式，都是必须回答的问题。

**Q: Notion 接入 MCP 这件事说明了什么？**
A: 它展示了 Agent 带来流量的现实图景：能实际干活的 Agent 会产生大量访问，产品团队必须考虑系统承载和商业模式。为人类设计的限额与定价，未必适配 Agent 式的调用密度，这迫使团队重新审视自己的计量与防护方式。

**Q: 未来的 Agent 和我们今天用的有什么不同？**
A: Tibo 描绘的是一个全天候、理解目标、记住偏好、能从反馈中学习的助手。用户不必先想好每一步怎么安排，也不必自己搭一堆循环去调试工作流——那种手动编排只是眼下的过渡形态。

**Q: 所谓「循环、调试工作流只是过渡」，是什么意思？**
A: 意思是现阶段用户要自己反复设置循环、手动调试流程，是因为系统还不够理解目标。长远看，你想要的系统应当围绕「你想达成什么」去学习，而不是要求你先把执行步骤想清楚再交给它。

**Q: 在 AI 时代，哪项技能的重要性在下降？**
A: Tibo 直接点出「打字快」。当生成与执行被大幅加速之后，速度不再是稀缺资源，理解和判断什么才算「好」反而越来越重要。换句话说，价值的重心从「写得多快」转向「判断得多准」。

**Q: 那什么变得更重要了？**
A: 品味与迭代能力。理解用户、判断质量、持续改进，这些都需要审美和取舍。同时岗位边界会变模糊，创造者不必只做设计或只做工程——一个人可以同时承担多个角色，稀缺的是把事情做对、做好的判断力。

**Q: AI 提效会不会反而让人更累？**
A: Tibo 明确不希望如此。Agent 越多、产出越快，不代表工作就更好；他的期望是 AI 能减少干扰，让人少开会、好好休息，把注意力留给真正想做的事，而不只是催人「每秒多发一个 prompt」。

**Q: Dot 是什么？它在 DevDay 上做了什么？**
A: Dot 是 Tibo 提到的他自己的一个 Agent/助手。在 DevDay 现场演示开始前五分钟，它发现 ChatGPT 线上系统出了故障，并主动询问「嘿，线上系统出故障了。要我试着修一下吗？」这类主动发现异常并提议行动的行为，是「环境人工智能」的一个直观样本。

**Q: Tibo 当时让 Dot 自动修复了吗？**
A: 没有。他没有让它动手，而是联系工程团队去排查。这个细节很关键：AI 可以第一时间发现问题并主动提议，但涉及线上系统的实际操作，是否授权、由谁负责，仍然掌握在人手里。

**Q: 什么是「环境人工智能」（ambient AI）？**
A: 从这期的语境看，指的是 AI 不再只在对话框里被动等待指令，而是持续在线、感知所处的环境与状态、在关键时刻主动介入并提供帮助。Dot 提前发现故障就是这种形态：它不需要被明确询问，就能注意到异常。

**Q: Agent 成为主要用户后，产品团队最该关注什么？**
A: 系统承载、商业模式与安全边界。流量来源从人变成 Agent 后，压测、限额、计费、权限与审计都要重新设计；同时要「为安全和人类需求设计 AI」，让自动化能力落在可控、可解释、可兜底的框架里。

**Q: Tibo 对人与技术关系的总体态度是什么？**
A: 他谈的是「落地」而不只是「能力」：Agent 要真正进入工作与生活，需要在产品发布、团队协作和真实使用场景中被检验。技术应当服务于人的目标与需求，而不是单纯地追求更高的产出速率。

**Q: 这一期为什么值得听？**
A: 它把「Agent 成为互联网主要使用者」这个趋势，具体落到了产品分发、工作技能、人机分工和安全性上，并用 Dot 在 DevDay 的临场案例，让抽象判断变得可感。对做产品、做 AI 落地的人来说，这是一个重新设定问题框架的机会。
