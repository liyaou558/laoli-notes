> 本期为「跨国串门儿计划」克隆节目 #714，中文声线转述原 The Pragmatic Engineer 对 OpenAI Codex 创始团队成员 Tibo Sottiaux 的英文访谈，原内容更新时间 2026-09-09，时长约 59 分钟。Tibo 目前负责 OpenAI 的 Core Products & Platform 组织（含 Codex）。本笔记基于 show notes 与金句整理，非完整转录稿。

## 一、核心观点

1. **harness 总是比模型领先一步。** Tibo 强调 harness（模型外层的脚手架）的作用不是替代模型，而是通过护栏、工具、developer message 和执行环境，让模型"已有的能力"变得更可靠、更高效、更符合用户预期。它与模型能力是一对纠缠关系：随着模型本身变强，原本必须写在 harness 里的引导逻辑会逐渐减少，脚手架被"拆掉"或变薄。但他也指出，harness 往往会先用工程手段把"未来模型才能解的问题"搬到今天实现——所以它总能领先模型半步。"harness 总是比模型稍微领先一点。"

2. **Rust 是 Agent 与产品之间的边界。** Codex 选择 Rust 并不只是为了性能，而是为了让 Agent 核心拥有更强的正确性、安全性和可扩展性。更关键的是架构原则：把"Agent 本身"和"产品"清晰隔离开，让 Agent 脱离任何特定产品也能独立存在。Tibo 认为这种解耦能避免两者过度耦合、为后续创新留出空间。"但把 Agent 本身和产品清晰地隔离开，让它脱离产品也能独立存在，这是一个非常重要的原则。"

3. **开源是为了参与正在变化的社区。** Codex 选择把 CLI、SDK 和应用服务器开源，不只是为了收集贡献者。Tibo 的逻辑是：代码 Agent 正在改变"代码本身"的作用，OpenAI 必须亲自进入这个社区、直接体验开发者遇到的问题，同时让外部开发者一起探索"优秀 harness 应该长什么样"。"如果我们真能做成功，开源本身会改变，代码本身的作用也会改变，所以身处这个社区之中显得很重要，而不是跟它脱节。"

4. **靠真本事赢，而不是靠模型绑定。** Codex 支持多个模型提供商，用户无需为了尝试新模型而更换整套工具，这降低了迁移成本；反过来，这也迫使团队同时在模型、harness、产品体验和开源生态四条线上保持竞争力，而不是躺在自家模型上吃老本。"我喜欢靠真本事去赢，而不是靠绑定去赢。"

5. **code review 正从代码审查变成意图讨论。** 正确性、安全性和复杂依赖关系的检查，越来越可以由 Agent 自动完成；人类更重要的工作，转向讨论"这个功能是否值得做""架构意图是否正确""团队是否对系统必须满足的不变式达成共识"。这些讨论完全可以在 PR 之外进行。"我觉得这种讨论完全可以在 PR 之外进行。没必要非得围着代码聊。"

6. **维护成本下降，重构和犯错会变得更便宜。** 依赖升级、安全补丁和大规模代码修改，未来可能被 Agent 自动完成，软件生命周期进入"压缩"状态。由于重构成本降低，团队可以更频繁地调整架构，愿意推倒重来；但抽象、边界和不变式仍然重要——因为一旦放松，快速改动会迅速积累成技术债。"所以犯错的成本，我认为是在下降的。"

7. **软件的生命周期正在被压缩。** 过去一个系统从小团队扩展成大型工程，需要较长时间补齐文档、流程和架构；现在 Agent 可能在一个周末就让大量代码同时涌入系统，工程团队必须更早考虑边界、维护与协作方式，否则规模会先于规则到来。"现在就像突然爆发一样，一下子就有 100 个 Agent 在给这套东西做贡献。"

8. **最重要的能力是快速理解和持续追问。** 给想进入 Codex、OpenAI 或 AI 初创公司的工程师，Tibo 的建议不是只熟练使用工具，而是保持对系统运作方式的极深好奇心，训练自己快速读懂新代码库的能力，并通过不断追问"五个为什么"建立对系统的清晰理解。"我觉得有两件事很重要，一是对事物运作方式抱有极深极深的好奇心，二是能训练自己非常快速地理解事物的能力。"

## 二、关键问答

**Q: 你为什么从谷歌、DeepMind 来到 OpenAI？早期经历对做 Codex 有什么影响？**
A: Tibo 的路径横跨应用数学、创业、研究基础设施、模型与产品工程。在谷歌他参与提升移动端网络速度的项目，后来到地图团队负责评价系统；在 DeepMind 长期做研究基础设施与工具，也参与过早期大语言模型对话系统的内部探索。这些经历让他既能理解研究侧的模型能力边界，又习惯从产品与基础设施的角度思考问题，最终被 OpenAI 的动手氛围吸引。

**Q: 早期的 ASWE 项目是怎么逐渐变成 Codex 的？**
A: Codex 最初是内部的研究项目，出发点更接近"让模型真的能动手改代码、跑命令、完成任务"。随着模型能力提升和 harness 不断补强，这套内部工具从实验逐步走向可交付的产品形态。Tibo 是 Codex 作为产品刚起步时的早期创建者之一，此后持续带领 Codex 团队至今。

**Q: 为什么 Codex 的核心 Agent 要用 Rust 编写？**
A: Tibo 说选 Rust 并不只是为了性能，更重要的是正确性、安全性和可扩展性——Agent 核心要长期稳定运行、处理并发与不确定性，语言层面的内存安全和类型系统能提供更强保证。同时把 Agent 核心独立出来、与产品清晰隔离，也让它能脱离具体产品独立存在，为后续创新留下空间。

**Q: Codex CLI、SDK 和应用服务器为什么选择开源？**
A: 除了获取社区贡献，更重要的是"参与正在变化的社区"。Tibo 认为代码 Agent 正在改变代码本身的作用，OpenAI 需要直接进入开发者圈子、亲身体验他们遇到的问题，也让外部开发者一起探索优秀 harness 该是什么样。如果真做成功，开源形态和代码的作用都会变，所以不能与这个社区脱节。

**Q: 为什么 Codex 不绑定 OpenAI 自家模型？**
A: 支持多模型提供商，能让用户不必为了尝试新模型而更换整套工具，降低迁移成本；对团队而言则是压力测试——必须在模型、harness、产品体验和开源生态上同时保持竞争力。"我喜欢靠真本事去赢，而不是靠绑定去赢。"这也是对外部模型趋势保持敏感的一种方式。

**Q: 你反复提 harness 提供"拐杖"，那具体指什么？**
A: harness 指模型外层的护栏、工具、developer message 和执行环境，作用是让模型已有的能力变得更可靠、更高效、更符合用户预期。它不是替代模型，而是把工程手段用来弥补模型当前的不足。随着模型变强，原本必须写死在 harness 里的引导逻辑会逐渐减少，脚手架也因此变薄。

**Q: 既然模型在变强，harness 会不会最终被淘汰？**
A: Tibo 的判断正相反——harness 往往先用工程手段把"未来模型才能解的问题"拉到今天实现，所以它总是比模型稍微领先一点。等模型追上来，那部分脚手架被删掉，团队再为下一段时间做新的工程补强。这是一个不断循环、循序渐进的过程，而不是一次性的收尾。

**Q: AI 会怎样改变 code review 这件事？**
A: 正确性、安全性和复杂依赖关系的检查，越来越能由 Agent 自动完成，人类更重要的价值转向"意图层"：这个功能值不值得做、架构方向对不对、团队是否对系统必须满足的不变式达成共识。Tibo 认为这类讨论完全可以在 PR 之外进行，不必非得围着代码逐行聊。

**Q: 维护成本下降后，工程组织会发生什么变化？**
A: 依赖升级、安全补丁和大规模代码修改未来可能被 Agent 自动完成，重构成本随之降低，团队可以更频繁地调整架构。但抽象、边界和不变式依然重要——因为改动变便宜后，错误的改动也会变多。结果是"犯错的成本在下降"，团队更愿意推倒重来，同时也更需要清晰的设计约束。

**Q: 软件生命周期被压缩，具体会带来哪些挑战？**
A: 过去系统从小团队长成大型工程需要较长时间补文档、流程和架构；现在 Agent 可能在一个周末就让大量代码同时涌入，规模先于规则到来。"一下子就有 100 个 Agent 在给这套东西做贡献"，工程团队因此必须更早考虑边界、维护和协作方式，否则很快会陷入失控。

**Q: Codex 在 OpenAI 内部是怎么融入日常工作的？**
A: Codex 被接入 OpenAI 内部的文档、Slack、代码库和新员工入职流程，成为团队成员日常处理任务的接口。它不只是外部开发者手里的工具，也是内部"吃自己狗粮"的核心产品——Tibo 自己也用 ChatGPT Work 和 Codex 管理日常工作，通过真实使用不断发现 harness 需要补强的地方。

**Q: Codex 与 ChatGPT 合并时遇到了什么系统挑战？**
A: 两者原本是独立演进的系统，合并涉及身份、权限、上下文、数据流和产品边界的重新梳理，工程复杂度显著上升。Tibo 在节目中把它作为"产品融合"的典型案例拆解：既要保留各自的能力优势，又要让用户感知为统一的体验，这需要大量架构层面的取舍与协调。

**Q: 你怎么用 ChatGPT Work 和 Codex 管理自己的日常工作？**
A: Tibo 把两者当作日常工作的基础设施：用 ChatGPT Work 处理信息梳理与任务管理，用 Codex 直接改代码、跑命令、完成工程任务。他强调这些工具不是为了演示，而是真正嵌入他作为 Core Products & Platform 负责人的工作流，帮助他在团队管理和工程推进之间保持效率。

**Q: 给想加入 Codex、OpenAI 或 AI 初创公司的工程师，你有什么建议？**
A: 不是只熟练使用工具。Tibo 认为有两件事最重要：一是对事物运作方式抱有极深的好奇心，二是训练自己非常快速地理解事物的能力——快速读懂新代码库、通过不断追问"五个为什么"建立清晰理解。"我觉得有两件事很重要，一是对事物运作方式抱有极深极深的好奇心，二是能训练自己非常快速地理解事物的能力。"

**Q: 如果只能给工程师留一句话，你想说什么？**
A: 保持好奇心，并持续追问。在 AI 让代码变便宜、让工程节奏变快的时代，稀缺的是"真正理解系统"的人：能快速摸清一个陌生代码库、能用"五个为什么"追问出设计意图、能判断架构边界和不变式是否成立。工具会不断换代，这种理解力才是长期资产。
