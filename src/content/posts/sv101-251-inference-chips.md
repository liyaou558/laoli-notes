## 一、核心观点

### 1. 训练与推理对芯片的要求，本质上是两种生意

训练时代没人能靠训练本身拿到商业回报，所以训练成本是"不可量化"的，大家只赌最强大集群换来最强模型；而推理是一笔能算清的账——用户愿意为每百万 token 付多少钱，我推出来这百万 token 要花多少钱（买 GPU 的钱 + 耗电）。因此训练关心的是算力与海量数据带来的并行度，推理关心的是带宽和性价比。本质原因是语言模型 token 生成是严格自回归的：必须知道上一个 token 的结果，才能推出下一个；每产生一个 token，都要把整个模型权重（例如 1.6T 参数）从存储介质搬进计算单元一次。带宽而不是算力，成了 decode 阶段的第一性约束。

### 2. Prefill 与 decode 是两种截然不同的计算模式

prefill 阶段所有 token 都已知，可以并行处理，读一次模型就能把整段 prompt（哪怕是一篇长文）同时算完；deep learning 也偏爱这种大矩阵相乘的算力密集负载，正好长在 GPU 的甜点区。到了 decode，必须一个词一个词地出，每次都要把整个权重读一遍，算力根本用不满。GPU 的对策是做 batching：并行收集一万个用户的请求，把这一万人的第一个、第二个、第三个 token 分别凑在一起算。代价是单用户的延迟被别人拖累——你等的不是自己那一个 token，而是一万个 token 里最慢的那一批。这也是 agent 与 reasoning 场景下，用户对推理速度的抱怨来源。

### 3. SRAM / DRAM / HBM：三种介质是在三种代价之间做选择

DRAM 是内存条，容量大但离计算远，来回取数慢；HBM 把 DRAM 搬到了计算芯片旁边并开了很多通道，容量大、速度快，代价是贵且全球产能极度紧张，现在 NVIDIA 高端 GPU 用的就是它；SRAM 可以直接坐在计算芯片内部，最快，但存一个 bit 要用 6 个晶体管（DRAM 只需 1 晶体管 + 1 电容），占面积是 DRAM 的几十倍到上百倍，所以单芯片容量比 HBM 低两个数量级。一句话总结：DRAM 便宜但慢，HBM 快但贵且抢不到货，SRAM 最快但装不下。真正的关键不是介质本身，而是"局部性"——把存储放到计算芯片内部，等于把封装级的走线换成光刻出来的片内走线，在线密度、成本和能耗上都是质变。

### 4. 业界为什么在向 SRAM 收敛

两位嘉宾认为，Groq、Cerebras 以及 d-Matrix、MetaX 等新兴推理芯片公司，还有大厂的 TPU、Trainium，本质上都看到了同一个问题：未来的 AI 系统对带宽有巨大需求，而 SRAM 在带宽绝对值与"每块钱买到的带宽"上，比现有其他存储介质高两到三个数量级。翻看各家已发布的芯片，每一代的 SRAM 都在变大；谷歌在博客里明确说要把 SRAM 更多用来存 KV cache，别家也有各自的设想。嘉宾自己创业的项目同样选择 SRAM 路线：单芯片放几百 MB SRAM（约 500MB），而 FP8 量化后的模型约是 TB 量级，两者一除，需要上千颗芯片才能把整个模型装下——于是"如何用某种拓扑把上千颗芯片连起来、让片间通信不成为瓶颈"，就成了工程核心。

### 5. Groq 与 Cerebras 的分歧点：静态编译调度 vs 晶圆级集成

大家都经历了同一个思想实验：SRAM 牺牲单芯片容量，那就把系统做得足够大（几百上千颗芯片）来放模型；可系统一大，效率瓶颈就卡在通信调度上——芯片只存着东西不会产生 token，还得把权重读出来算。在这一点上两家分道扬镳。Groq 的思路是把调度放到运行之前：由编译器在编译期排好"哪个时钟周期算、哪个时钟周期通信"，运行时就没有调度开销，同时把确定性（determinism）做到极致——SRAM 加定制设计，让读数据的延迟抖动远小于 DRAM。Cerebras 则更简单粗暴：既然通信代价来自"一个机柜几百颗芯片的物理距离"，那就把整块晶圆做成一颗芯片（wafer-scale），物理距离短了，能出的连线带宽自然更好。

### 6. 两条路线的时代局限，最后都折算成 token 成本

Groq 成立于 2016 年，做技术决策时 Transformer 还没出来，所以它押注编译器静态调度的假设比较脆：MoE 让每个 token 在运行时从 128 个专家里动态挑 8 个，这件事编译期根本无法预测，只能保守地把 token 都送过去导致部分芯片空转，或者换一种切分方式（而当前模型用其他维度很难切干净）。Cerebras 的挑战则是良率与成本：传统单芯片尺寸极限约 800 mm²，一片晶圆能切出三四十到五十颗芯片，正常情况下只要良率达到 50% 就能切出 20 颗好的；而整片晶圆做一颗产品，它要接受 30% 的缺陷点仍能用，一旦整片达不到良率要求，整片晶圆就作废，制造成本极高——这不是一次性掩模（mask）成本被摊薄的问题，而是"每造 10 个可能有 9 个不能用"。所以 Groq 要为确定性打折扣，Cerebras 要为良率成本打折扣，折扣最终都打到 token 成本上。

### 7. NVIDIA 为何花大价钱 acqui-hire Groq，以及 CUDA 一定会被绕过

嘉宾的判断很直接：NVIDIA 和 GPU 的价格无法很好解决推理带来的新的大带宽需求，Jensen 清楚未来推理里算力不是唯一，需要补上带宽这块能力；而 CUDA 这样的大护城河既是壁垒，也是创新的包袱——即使 NVIDIA Research 里 Bill Dally 团队早就发表过大量架构层面创新（比如 CGRA 相关工作），在成熟公司内部把颠覆式 research idea 推给产品团队依然极其困难，所以干脆 acqui-hire 一个与原有团队没有关系的新技术团队（据报道涉及约 200 亿美元）。绕过 CUDA 是"百分之百会发生"的事：TPU、Trainium 从没打算兼容 CUDA。核心变化在于天平——训练时代大家更愿意为软件的"好用"买单，推理时代更愿意为性能和性价比买单，所以连 DeepSeek 都用 GPU 却更愿意直接写底层 PTX 汇编。

### 8. 评价一款推理芯片的框架：成本、速度、耗电与利用率

嘉宾给出的优先级是：第一看每个 token 的成本，第二看单用户推理速度，第三看耗电量；利用率（MFU / MBU）会影响成本，但最终用户只关心成本。因为未来系统是异构的，衡量芯片好坏必须放在系统层面。算力跑不满的原因有三层：一是计算与访存的比例没有长在 GPU 的甜点上，被带宽卡住（Roofline 模型）；二是推理由大量细碎算子组成——每秒两三百 token 时每个 token 对应的计算任务非常细碎，调度损失比训练的大矩阵相乘大得多；三是芯片间互联等待，"芯片在等数据"时计算单元只能空转，而 MFU 基本只统计矩阵乘法，一旦矩阵乘法空转，利用率数字就下来了。这三者分别属于硬件设计、软件层和使用者。

### 9. OpenAI 的路径：HBM4 与 Dark Silicon，把异构做进一颗芯片

OpenAI 在录制当天（6 月 24 日）与博通发布了首颗自研推理芯片，它没有走 SRAM，而是把 HBM4 带宽堆到单封装每秒 15.4TB。原因是它最敏感的是电：美国数据中心缺的不是资本和空间，而是电力供给，所以要用同样的电产出更多 token。这颗芯片每瓦/MW 能产出的 token 数高于 NVIDIA 对应的 Rubin 架构。它是通用推理芯片，把 prefill、decode、attention、FFN 全部用一颗芯片包了，还专门支持小维度矩阵乘法以在 batch size 较小时保持性能，下一代甚至要支持训练；它提出用 "Dark Silicon（暗硅）" 的思路——做不同事时关掉部分单元降低功耗，把异构从系统级搬进了芯片内。代价是单位成本的 token 产出不占优，是"用更多成本买电效率"的取舍。

## 二、关键问答

**Q：训练芯片和推理芯片，为什么需要两种不同的芯片？**
**A：**两个层面。商业上，训练没有直接商业回报、成本不可量化，推理则是能算清的账；技术上，训练有海量数据提供足够并行度，可以靠一次读权重做大量计算，因此关心算力；推理的 decode 是严格自回归的，每出一个 token 都要把整个模型权重读一遍，因此第一性约束是带宽而非算力。

**Q：用户提示"帮我出一份采访提纲"，GPU 和使用专业推理芯片的体验差别在哪？**
**A：**prefill 阶段整句话可并行喂进去，读一次 HBM 就能同时处理所有 token，GPU 算力能吃满。但到了真正吐字阶段，每个词都要把整个模型重新读一遍。GPU 只能靠 batching 把上万个用户的同一位置 token 凑一起算，于是你的单 token 延迟要等同一批里最慢的用户，这正是"推一个 token 为什么这么慢"的核心。

**Q：SRAM、DRAM、HBM 应该怎么理解？**
**A：**区别在于离干活的地方有多远。DRAM 是内存条，装得多但来回取数慢；HBM 把 DRAM 搬到计算芯片旁边并开了大量通道，容量大速度也快，代价是贵且产能紧张；SRAM 直接坐在计算芯片里，最快，但存一个 bit 要 6 个晶体管，面积代价是 DRAM 的几十到上百倍，所以容量只有 HBM 的几分之一到两个数量级差距。

**Q：为什么说带宽的关键是"局部性"？**
**A：**Bill Dally 的原话是"计算机体系结构就像房地产，关键是位置、位置、位置"。CPU 的 cache 就是时间局部性与空间局部性的应用。而在 AI 推理的 decode 阶段，算法层面的时间与空间局部性都被抹平了，所以必须在架构上用硬件局部性来弥补——把模型权重放进 SRAM，本质就是把存储搬到计算芯片内，用光刻的片内走线替代封装走线。

**Q：Groq 和 Cerebras 解决大集群通信问题的思路有什么不同？**
**A：**Groq 把调度提前到编译期：编译器在运行前就把每个时钟周期该做什么计算、什么时候通信全部排好，运行时没有调度开销，同时把确定性做到极致，数据读出延迟抖动极小。Cerebras 更直接：通信代价来自一个机柜几百颗芯片的物理距离，那就把整块晶圆做成一颗芯片，距离缩短后连线带宽自然更好。

**Q：MoE 为什么会让 Groq 的静态编译调度吃亏？**
**A：**MoE 网络有大量专家，每个 token 在运行时才决定激活 128 个专家中的 8 个，这个选择编译期无法预测。而单颗芯片的 SRAM 容量放不下整个网络，必然出现"某些专家在某几颗芯片上"的调度问题。若用静态方式处理这种动态性，要么非常保守地把 token 都送过去导致部分芯片空转，要么换一种模型切分方式，而当前模型很难用其他维度切干净。

**Q：Cerebras 为什么成本比 Groq 还高？**
**A：** wafer-scale 生产会遇到良率这个关键参数。传统单芯片极限约 800 mm²，一片晶圆可切出三四十到五十颗，50% 良率还能出 20 颗好的；而整片晶圆做一颗产品，它要接受 30% 缺陷点仍可用，但这与晶圆实际缺陷率不一定匹配，且一旦达不到要求整片作废。这不是可摊薄的掩模成本，而是量产阶段每个产品的实际成本问题，还要额外负担绕行坏核的软件与机柜集成成本。

**Q：NVIDIA 为什么要花约 200 亿美元 acqui-hire Groq？**
**A：**因为 GPU 的架构与价格无法很好满足推理新增的大带宽需求。Jensen 意识到未来推理里算力不是唯一，需要补带宽能力。NVIDIA Research 虽然早就有相关架构创新（如 CGRA 论文），但在成熟公司内部把颠覆式想法推给产品团队极难，CUDA 既是护城河也是创新包袱，所以直接买下一个与原团队无关的新技术团队是很好的决定。

**Q：绕过 CUDA 有可能吗？**
**A：**百分之百会发生。TPU、Trainium 从设计上就没打算兼容 CUDA。难点不在问题数量而在问题类型：只要把 Transformer 里的所有算子在新芯片上写出来，商业逻辑就通了，且 AI 编程能力正在大幅加速算子与运行时的开发。更本质的是天平变化——推理时代大家更愿意为性能性价比买单，而不是为难用的软件让步，DeepSeek 甚至直接在 GPU 上写 PTX 汇编。

**Q：一家芯片公司行不行，你会问哪两个问题？**
**A：**第一，你的 tokens per second 能做多快、多便宜；第二，在芯片组成的系统里，每 token 的价格和单用户的每秒推理速度是多少。嘉宾强调很多实际在做推理芯片的公司根本没有这个数字，因为它必须先站在系统层面才回答得出来，而不是停留在芯片的算力、带宽、容量参数上。

**Q：推理速度现在还是瓶颈吗？用户觉得已经够快了。**
**A：**这不是"让交互从一分钟变一秒"，而是"在同一分钟内思考更多次"。agent 大规模爆发后大量 token 不是给人读的，而是给模型自己（思维链）或别的 agent 读的，人对速度的感知上限约每秒 100 token。真正的约束是时间：如果判断明天股市需要两天时间，答案就毫无意义。所以在确定的时间卡点内产出更多智能，就翻译成了"要更快"。

**Q：芯片的理论算力和实际跑出来的差距，去哪儿了？**
**A：**三部分原因。一是计算与访存比例没长在 GPU 甜点上，被带宽卡住（Roofline）；二是推理由大量细碎算子组成，每秒两三百 token 时每个 token 的任务非常碎，调度损失比训练的大矩阵相乘大；三是互联等待，数据从别的芯片传来不及时，计算单元空转。因此既要看访存带宽利用率（MBU），也要看算力利用率（MFU），两者都到 100% 才没有问题。

**Q：芯片的完整设计流程是什么样的？**
**A：**先从需求分析开始，明确芯片定位与要解决的问题；然后是高层系统架构（未来交付的可能是服务器甚至集群），再拆到微架构：计算核怎么设计、矩阵单元与存储单元怎么摆、用什么指令集、SRAM 放在哪；确定 feature list 后进入 RTL 编码（实际编码可能只要两三个月）；随后是大量验证（测试用例或形式化证明），然后后端做布局布线、SDC 检查；再流片出掩模，量产回来后是封装、测试、良率筛选，最后还有 PCB、交换芯片、供电散热与集群组网。

**Q：为什么现在做新架构芯片比 80 年代、比 Intel Itanium 时代更容易成功？**
**A：**两点。经济上，今天有一个单一的大应用（AI），几百万美元的流片费和上亿的研发成本能被清楚地摊薄论证，而在过去没有这样的大应用。软件上，过去 Intel 要保证几千款应用在上面都不掉队，今天只有一个大应用甚至只有 Transformer 这一类结构相对简单的模型（几十层几乎一样的层），且 AI 编程能力正在加速 kernel 优化，软件栈的门槛大幅降低。

**Q：国内创业做推理芯片，优势在哪里？**
**A：**一方面供应链更完善、供应商更多，数据中心选址、用水用电等基础设施能力更强，中国也是能自己养起来的巨大市场；另一方面国内最强模型（以 DeepSeek、智谱为代表）在架构层面更开放，可稳定获取的最好 AI 模型 API 也是开源的，方便新芯片拿来自证效果。相反，Groq、Cerebras 当年在美国面对的是最主流模型不开源、只能吃开源小市场的窘境。

**Q：OpenAI 为什么选最贵的 HBM 路线，而不是 SRAM？**
**A：**因为它的第一性约束是电，而不是钱。美国数据中心缺的是电力供给而非资本与空间，所以要在确定的电力产能内产出最多 token，关注的是"电转成 token 的效率"。SRAM 的优势在于每块钱买到的带宽高几个数量级，但容量受限，做通用芯片很吃亏；OpenAI 选择用更贵的存储换通用性、换每瓦 token 数，代价是 per dollar 的 token 产出不占优。

**Q：OpenAI 这颗芯片还有哪些细节？**
**A：**它是通用 AI 推理芯片，与 GPU 接近，能跑各种模型甚至 demo 跑游戏；把 prefill、decode、attention、FFN 都用一颗芯片包了，并支持小维度矩阵乘法以在 batch 小时保持性能，下一代还要支持训练。它强调电效率，每瓦/MW 产出的 token 多于 NVIDIA Rubin 架构；提出 Dark Silicon 暗硅思路，关掉部分单元降功耗。此外它用 AI（Codex）写了大量 kernel，从启动到流片只用了 9 个月。

**Q：SRAM 的窗口期会不会被 HBM 关掉？KV cache 的需求又在怎么变化？**
**A：**HBM 带宽虽然已经很好，但后续每代带宽从哪里来并不确定，它的连线不是光刻出的片内线，密度存在天然瓶颈，一定程度上已接近极限，所以才有 3D DRAM 这类方向；在带宽绝对值与性价比上 HBM 与各类 HBF 都很难追上 SRAM，SRAM 的短板始终是容量性价比。而 KV cache 方面，DeepSeek 新模型每一代的每 token KV cache 这次缩到了四分之一到八分之一，但长上下文的需求是动态且持续增长的，所以嘉宾不会优先用 SRAM 存 KV cache。

**数据与术语**
- 自回归：token 必须顺序产生；decode 每产一个 token 需读一遍整个模型权重。
- batching：GPU 把上万个用户请求的同一位置 token 凑批计算，代价是单用户延迟。
- 单用户推理速度：现有 GPU 方案约 50–100 token/s；人类阅读上限约 100 token/s；Cerebras 号称可达 750 甚至 2000 token/s。
- 目标量级：速度提升 2–3 个数量级（从几十 token/s 到 1000 甚至 10000 token/s），性价比提升约 10 倍（约一个数量级）。
- SRAM vs DRAM：SRAM 6 个晶体管存 1 bit，DRAM 1 晶体管 + 1 电容；SRAM 单芯片容量比 HBM 低约两个数量级；带宽性价比比 HBM 高 2–3 个数量级。
- 单芯片 SRAM 约几百 MB（约 500MB）；FP8 量化后模型约 1TB，需上千颗芯片。
- 单芯片尺寸极限约 800 mm²；一片晶圆可切三四十至五十颗；Cerebras 接受约 30% 缺陷点。
- MoE：128 个专家中激活 8 个（运行时决定）。
- TCO = CAPEX（芯片、机房一次性投入）+ OPEX（五年功耗 × 时间 × 电价，含散热）；电费占 TCO 比例：中国约 1/3，美国约 2/3。
- Roofline 模型、MFU（Model FLOPs Utilization）、MBU（Memory Bandwidth Utilization）。
- 芯片周期：传统约一年半到两年；OpenAI 号称 9 个月。
- 芯片流程术语：需求分析、高层架构、微架构、feature list、RTL、验证（形式化验证/测试用例）、后端布局布线、SDC 检查、流片（mask/掩模）、封装测试、良率、PCB、集群供电散热组网。
- 硬件名词：HBM、HBM4、HBF、3D DRAM、SRAM、DRAM、KV cache、PTX 汇编、CGRA、Dark Silicon（暗硅）、wafer-scale、local minimum、locality（时间/空间局部性）。
